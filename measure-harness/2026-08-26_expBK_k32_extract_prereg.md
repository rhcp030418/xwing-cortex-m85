# 사전등록 — 실험 BK (K32): `StateExtractBytes` 비트-인터리브 해제 교차 배치

> 작성 2026-08-26, **측정 전**. 장부 신규 ID **K32**.
> 선행: expBJ(분모 실측 885.81 cyc/168 B, IPC 0.97), expBE(발행 모델), expBB(재정렬 도구).

---

## 1. 분모 (expBJ §2, DTCM 기준 실측)

| | 값 |
|---|---:|
| `KeccakF1600_StateExtractBytes(0,168)` | **885.81 cyc** = 42.18 cyc/lane |
| squeeze 배관 중 비중 | **93.2%** |
| 호출 수 | **28회/연산** (expAQ) |
| **연산당 총량** | **24.8 kcyc** = keygen 3.98% / encaps 2.51% / decaps 3.13% |

K19(순열)는 IPC 1.66 으로 닫혔지만 **이 커널은 IPC 0.97** 이다.

## 2. 원인과 방법

`fromBitInterleaving` 은 `eor → and → eors → eor` **4단 직렬 사슬**을 8번 돈다.
앞 4블록은 `r4`(x0), 뒤 4블록은 `r5`(x1)에 대한 것이고 **두 반쪽은 서로 독립**인데,
**둘 다 임시로 `r3` 하나를 쓰기 때문에** WAR/WAW 로 직렬화된다.

→ x1 사슬에 임시 `r6` 를 따로 주고 **두 사슬을 1:1 교차 배치**한다.
명령 수는 40으로 **불변**이다(레지스터 이름만 바뀐다).

`r6` 사용은 안전하다: 호출자 `KeccakF1600_StateExtractBytes` 가 `push {r4-r8, lr}` 로
저장하며, 호출 구간에서 살아 있는 것은 `r8` 뿐이다(`mov r8,r3` → `bl` → `and r3,r8,#7`).

### 2.1 모델 (규칙 5 — baseline 재현 확인)

| | 모델 | 실측 |
|---|---:|---:|
| 원본 | **41.0** | **42.18** (비 0.97) |
| r6 분리 + 도구 재정렬 | 37.0 | — |
| **손교차 배치** | **26.0** | — |

**모델이 baseline 을 3% 안에서 재현하므로 이 모델의 스케줄을 보드에 올린다.**
손교차 판의 예측 절감은 **−36.6%** 다.

## 3. 통합 방식

`keccak_squeezeblocks` 는 항상 `offset 0`, `length = rate`(168 또는 136)로 부르며
**둘 다 8의 배수**다. 따라서 whole-lane 전용 경로만 만들면 된다.

```c
if (k32_mode) KeccakF1600_StateExtractLanes_bk(s, h, r / 8);
else          KeccakF1600_StateExtractBytes(s, h, 0, r);
```

**양쪽이 같은 분기 비용을 물므로 같은 ELF 안 A/B 가 성립한다.**
`KeccakF1600_StateExtractBytes` 원본은 손대지 않는다(absorb 쪽 partial 호출이 그대로 쓴다).

## 4. 사전 고정 kill gate

### 4.1 성능

- **BK-1: `extract(0,168)` 단가 ≥ 20% 절감** (885.81 → 708.6 이하).
- **BK-2: full X-Wing 세 연산 중 하나라도 회귀하면 채택 금지.**
- **BK-3: 세 연산 중 최소 두 곳에서 ≥ 0.70% 개선.**

셋 다 넘어야 채택한다. 못 넘으면 **K32 를 이 접근으로 종료한다.**

### 4.2 정확성 (전부 필수)

- **무작위 200 상태에 대해 원본 `StateExtractBytes(s,·,0,168)` 결과와 168 B 완전 일치**
- rate 136(SHAKE256) 경로도 같은 방식으로 일치 확인
- full X-Wing 8-seed 바이트 동일 + 암묵적 거부 동일, FIPS 203 KAT, `harness_fails = 0`

### 4.3 자원

- `.text` 증가 보고. 새 커널은 ITCM 예산 밖(.text)에 둔다.

## 5. 이것은 순수 재정렬이 아니다

규칙 9("손 asm 은 재정렬만")의 예외다. **임시 레지스터 하나를 추가로 쓴다.**
그 규칙의 취지는 커스텀 ABI 파손 방지인데, 이 커널은 파일 내부 helper 이고
새 함수로 따로 쓴다. **대신 §4.2 의 무작위 200 상태 바이트 일치를 필수로 둔다** —
명령 수 불변 검사만으로는 부족하다.

## 6. 바꾸지 않는 것

Keccak-f1600 순열, 상태의 비트-인터리브 표현, SHAKE 정의, `StateXORBytes`(absorb 쪽),
ML-KEM/X-Wing 정의. `toBitInterleaving` 에 같은 수법을 적용하는 것은 **별도 실험**이다.
