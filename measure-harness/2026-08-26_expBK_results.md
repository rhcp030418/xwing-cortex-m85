## 2. 왜 모델만큼 안 나왔나 — 모델이 낙관적이다

| | cyc/lane |
|---|---:|
| 원본 실측 | 46.51 (= 903.50 / 21 + 호출분) |
| 원본 모델 | 41.0 |
| **교차 배치 모델 예측** | **26.0** |
| **교차 배치 실측** | **35.46** |

**실현율 = (41.0 − 35.46) / (41.0 − 26.0) = 0.37.**
expBD 가 기록한 이 도구의 실현율 0.60 보다 **더 나쁘다.**

> **2026-08-26 반증 (expBL §3-1,2)**: 아래 추정은 **틀렸다.** shifted-operand ALU 는
> 평 ALU 와 처리율·지연이 **완전히 동일**하며(A=C, B=D 완전 일치) 서로 페어링도 된다.
> 실제 원인은 (a) `bfi` 가 듀얼이슈되지 않는 것과 (b) `fromBitInterleaving` 블록이
> 1.28 cyc/명령이라는 것이다. **BK 의 종료 판정은 사전등록 gate 로 한 것이므로 유효하다.**

### 2.1 가장 그럴듯한 원인은 shifted-operand ALU 다 — **미측정**

`fromBitInterleaving` 의 명령은 대부분

```
eor  r3, r4, r4, LSR #8      @ shifted register operand
eor  r4, r4, r3, LSL #8
```

형태다. expBA 는 `umaal`·`adds`·`ldr`·`str` 의 발행 규칙만 쟀고,
**shifted-operand ALU 는 재지 않았다.** expBE/BB/BK 가 쓰는 회계는
"ALU = 0.5 cyc, 100% 페어링"을 **shifted-operand 에도 그대로 적용**하고 있다.

만약 M85 에서 shifted-operand ALU 가

- 지연 2 cyc 이거나
- 다른 ALU 와 페어링되지 않는다

면 하한이 26 이 아니라 35 근처가 되어 **실측과 맞는다.** 그러나 **이는 추정이며 아직
측정하지 않았다.** 다음 실험(**expBL**)에서 직접 잰다.

> 이 문서는 그 추정으로 판정을 바꾸지 않는다. BK 는 사전등록된 gate 로 종료됐다.

## 3. 남는 것

- 커널 `gen/keccak_extract_bk.S` 는 **정확하고 17.57% 빠르지만 채택되지 않는다.**
  `k32_mode` 기본값 0 이므로 기본 경로는 원본이다.
- K32 를 다시 열려면 **새 사전등록 + 새 임계값**이 필요하다(규칙 3).
  expBL 이 발행 규칙을 고쳐 새 하한을 주면 그때 판단한다.

## 4. 부수적으로 확정된 것

expBJ 가 추정했던 **K24(squeeze→CBD 융합)의 표적 오류**가 이번 측정으로 뒷받침된다.
배관 950 cyc 중 886(93.2%)이 `StateExtractBytes` 이고, 그 안을 17.57% 줄였을 때
full X-Wing 이 0.41~0.69% 움직였다. 배관 전체를 없애도 상한은 그 몇 배 수준이다.

## 5. 미측정·한계

1. **shifted-operand ALU 발행 규칙 미측정**(§2.1). 이것이 이 실험의 가장 큰 미지수다.

4. `.text` 768,860 (BJ 빌드 765,404 대비 +3,456; 그중 커널 본체는 41 명령).
