## 2. 방법 — 재정렬 전용 스케줄러 (`expBB-src/resched.py`)

SLOTHY 를 쓰지 않았다. `slothy-2stream/README` §135 의 확정 원칙(14레지스터를 꽉 채운
손 asm 은 스필 추가 없이 스케줄러가 손대지 못함) 때문이며, **레지스터를 재할당하는
순간 이 커널의 ABI(입출력 r0–r7)가 깨진다.**

대신 **순서만 바꾸는** 도구를 만들었다.

- 레지스터 재할당 없음, 명령 추가·삭제 없음 → 의미 보존이 의존성 그래프의 정확성만으로
  보장된다. 명령 수 94 불변이 그 검증이다.
- 의존성: 레지스터 RAW/WAR/WAW + **플래그**(`adds`/`adcs` 캐리 체인) + 메모리
  (`[sp,#k]` 오프셋별, `strd` 는 2워드)
- `push`/`pop`/`sub sp`/`add sp` 는 **고정점**으로 두고 그 사이만 재정렬

### 2.1 모델이 baseline 을 재현하는지 먼저 확인했다

첫 판은 **처리율만** 넣은 모델이었고, 원래 순서를 **62 cyc** 로 예측했다(실측 ~96).
**모델이 baseline 을 2/3 밖에 설명하지 못하므로 그 스케줄은 보드에 올리지 않았다.**

빠진 것은 **지연(latency)** 이었다. SLOTHY 패치 v0.3 의 실측 근거를 그대로 넣었다.

| 생산자 → 소비자 | latency |
|---|---:|
| 곱셈 → **누산기**(umaal 의 RdLo/RdHi) | 1 |
| 곱셈 → Rn/Rm | 2 |
| load → 사용 | 2 |
| 그 밖 | 1 |

지연을 넣자 원래 순서 예측이 **84.0**(+ push/pop 고정점 ~12 = **96**)이 되어
**실측과 일치**했다. 그 뒤에야 재스케줄을 진행했다.

### 2.2 모델 예측 대 실측

| | 모델 | 실측 |
|---|---:|---:|
| 원본 | 96 | ~96 |
| 재스케줄 | 77 | **~74.3** |
| 절감 | −19.8% | **−14.80%** (shim 포함 기준) |

shim(≈35 cyc)이 분모에 들어간 A/B 이므로 본문 기준으로 환산하면 96 → 74.3 = **−22.6%**
로 모델(−19.8%)보다 오히려 좋다. **모델 오차 약 3%p** — 2026-08-17 의 30% 괴리와
대조된다(그때는 issue_rate 오판, 이번은 지연을 넣은 모델).

## 3. X-Wing 기준 투영 (실측 아님)

sqr 본문 절감 21.7 cyc/호출 × expAY 의 호출 수(X06 on):

| 연산 | sqr 호출 | 절감 | X-Wing 대비 |
|---|---:|---:|---:|
| keygen | 254 | 5,512 | −0.86% |
| encaps | 1,528 | 33,158 | −3.28% |
| decaps | 1,274 | 27,646 | −3.41% |

**full X-Wing 통합 A/B(BB-2)는 아직 하지 않았다.** 위는 투영이며 대표값으로 쓰지 않는다.

## 4. 정확성 상세

```
expBB correctness: mm=0 checks=1007
harness_fails=0, KAT ALL PASS
```

경계 7종: `0`, `1`, `p−1`, `p`, `2^255−1`, `2^256−1`, 교대 패턴.
무작위 1,000종: xorshift32, 8 limb 전체 랜덤(정규형 밖 입력 포함).
비교는 **limb 단위 완전 일치**다.

플래그 체인을 잘못 모델링했다면 특정 캐리 패턴에서만 깨질 수 있으므로 경계값 +
1,000 seed 를 방어선으로 뒀다.

## 5. 미측정·한계

1. **full X-Wing 통합 미실행**(§3). 다음 단계 BB-2.
2. `fe25519_mul` 은 아직 손대지 않았다 — 같은 도구로 처리 가능하며 여지 23.4%.
3. 모델의 지연 값(누산기 1 / Rn·Rm 2 / load 2)은 SLOTHY v0.3 의 값을 **차용**한 것이며
   이번에 독립 측정하지 않았다. baseline 재현이 유일한 검증이다.
4. `stm`/`push` 의 다중워드 차단 폭은 여전히 보수 가정이다(expBA §6).
5. 재정렬로 I-cache 라인 경계가 바뀔 수 있다 — 이번 A/B 는 같은 ELF 안이라 통제됐지만
   통합 시에는 AF 판례대로 배치 통제가 필요하다.
6. EK-RA8M1 한 개체, 이 배치 한정.
