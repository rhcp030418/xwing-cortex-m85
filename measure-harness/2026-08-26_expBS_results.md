> 측정 2026-08-26. 보드 EK-RA8M1, DWT CYCCNT, REP_N=100, 같은 ELF ABBA, 독립 flash/run 2회.
> 사전등록: `2026-08-26_expBS_k21_keccakx4_prereg.md` §3 (측정 전 고정).
> 현행 채택 baseline(X06+X01+X02+K31) 위에서 `mlkem_keccakx4_mode` 만 토글했다.

### 1.1 정확성은 완전히 통과했다

8-seed bytes-mm **0**, 암묵적 거부 mm **0**, smoke **0**, `harness_fails = 0`, KAT PASS.
**x4 경로는 옳고 느리다** — dummy lane 매핑도 정확하다.

## 2. 왜 느린가 — 표적보다 부대비용이 크다

사전등록 §2 의 표적은 **absorb 11.4k + 초기 squeeze 9.2k = 20.6 kcyc/연산**,
4-way 중 3개만 쓰므로 이론 상한 2/3 = 약 13.7 kcyc.

실측은 그 반대로 **+18.5 k(keygen) / +19.8 k(encaps) / +19.3 k(decaps)** 늘었다.

부대비용:

| 항목 | 회/연산 | 비고 |
|---|---:|---|
| dummy lane | 3 (행마다 1) | 4-way 중 25% 를 버린다 |
| `memcpy(states[j].ctx, batch.ctx[j], 200)` | 9 | K31 워드 복사여도 200 B × 9 |
| `extseed[4][34]` 구성 + `memcpy` | 12 | |
| 4-way 상태 4개(800 B) 스택 점유 | — | |

**4-way SHAKE 자체가 3-way 작업에 맞지 않는다.** 장부가 "AC x4 통합 실패"로 기록한
것과 같은 결론이며, **채택본이 바뀐 현행 baseline 에서도 같다**는 것이 이번 결과다.

## 3. K21 이 닫혀도 K20 은 열려 있다

| | 내용 | 상태 |
|---|---|---|
| K21 | **기존 4-way SHAKE 배칭**을 matrix-XOF 에 적용 | **종료(이번)** |
| K20 | **MVE 2-way permutation 자체를 새로 작성** | 열림 |

K20 은 명령열이 다르다(스칼라 Keccak 대신 MVE Keccak). dummy lane 문제도
2-way 면 3-way 작업에 1개만 남으므로 낭비가 25% → 이론상 더 작다.
**단, MVE Keccak permutation 을 새로 쓰는 것은 별도 과제다.**

## 4. 미측정·한계

1. x4 부대비용의 **내부 분해 미측정**(§2 는 항목 나열이며 각각을 재지 않았다).
2. dummy lane 을 없앤 **true x3** 은 미구현·미측정이다. 상한은 §사전등록 §2 의
   13.7 kcyc(평균 1.79%)이며, 이번 실측이 보인 부대비용 19~20 k 를 그보다 작게
   만들어야 한다 — **가능성은 낮아 보이나 측정하지 않았다.**
3. EK-RA8M1 한 개체, 이 배치 한정.
