## 2. 단계 CA-1 — **한 루프에서 증명한다**

### 2.1 대상

`intt_kyber_1_23_45_67_opt_m85` 의 `layer67_loop` (원본 소스에서 추출):

| | 값 |
|---|---|
| 본문 | **46 명령, 전부 MVE** |
| 스칼라 레지스터 | **5개** — `r0`(저장 포인터) `r11`(적재 포인터) `r8` `r9` `r12`(스칼라 피연산자) |
| 벡터 레지스터 | q0–q7 전부 |
| 트립 | 8 |
| **MVE 포트 시간** | 46 × 2 × 8 = **736 cyc** |
| 스칼라 포트 시간 | `le` 8회 ≈ **8 cyc** |
| **숨길 수 있는 여유** | **≈ 728 cyc** |

### 2.2 끼워 넣을 스칼라 스트림

`KeccakF1600_StateExtractLanes_bk` (expBK 커널, 정확성 1,049 검사 통과, 채택은 안 됨).

- 레지스터 **7개** (`r0`–`r6`), 벡터 레지스터 **0개**
- 단가 **35.46 cyc/lane** (expBK 실측)
- **겹치는 것은 `r0` 하나** → NTT 의 `r0` 을 `r7` 로 재배치하면 합 **12개 ≤ 14**
- **스필이 필요 없다.** 이것이 이 상대를 고른 이유다.

> 규칙 9("손 asm 은 재정렬만") 예외: **레지스터 이름 재배치를 한다.**
> 커널 내부 임시 레지스터이고 커스텀 ABI 를 건드리지 않으며, expBK 가 같은 성격의
> 변경(`r6` 추가 사용)을 1,049 검사로 검증한 선례가 있다. **§2.4 의 정확성 검사가 방어선이다.**

### 2.3 만드는 것 — 커널 3개

| | 내용 | 명령 수 |
|---|---|---:|
| **A** | layer67 본문 ×8 펼침, NTT 만 | 368 |
| **B** | Keccak extract lane ×16, 스칼라만 | 656 |
| **C** | **병합** — 위 둘을 하나로 엮음 | 1,024 |

16 lane 을 고른 근거: 16 × 35.46 = **567 cyc < 736 cyc**(여유 안).

### 2.4 사전 고정 kill gate

**정확성 (전부 필수)**

- **C 의 NTT 출력 = A 의 NTT 출력** (같은 입력, 벡터 메모리 바이트 완전 일치)
- **C 의 Keccak 출력 = B 의 Keccak 출력** (같은 입력, 바이트 완전 일치)
- 기존 전체 하네스 `harness_fails = 0`, KAT PASS

**성능**

- **CA-1a: `C ≤ A × 1.05`** — 즉 Keccak 656 명령이 **5% 이내 비용으로 숨는다.**
  (완전 은닉이면 C = A. 스칼라 포트가 567 < 736 이므로 이론상 C = A 다.)
- **CA-1b: `C < A + B × 0.5`** — 최소한 절반 이상은 숨어야 한다.

둘 중 **CA-1a 를 못 넘고 CA-1b 만 넘으면 부분 성공**으로 기록하고 확대 단계로 가지 않는다.
**CA-1b 도 못 넘으면 W03/W04/W05 를 종료한다.**

**자원**

- `.text` 증가 보고. 병합 커널은 루프를 펼치므로 커진다.

## 3. 단계 CA-2 — 확대 (CA-1a 통과 시에만)

CA-1 이 통과하면 다음을 **새 사전등록 없이** 이어서 한다. 임계값은 지금 고정한다.

1. **대상 확대**: `intt` 의 저-레지스터 루프 3개(`layer67`·`layer23`·`layer1`,
   동적 MVE 의 67.8%)와 `ntt` 의 2개(`layer12`·`layer67`, 65.3%).
2. **스칼라 스트림 교체**: Keccak 대신 **`fe25519_mul`**(X25519 의 26.1%).
   레지스터 14개라 **2개 스필**이 필요하다 — expBM 의 프레임 평탄화 수법을 쓴다.
3. **통합 A/B**: full X-Wing 에서 잰다.
   - **CA-2a: 세 연산 중 하나라도 회귀하면 채택 금지.**
   - **CA-2b: 세 연산 평균 ≥ 1.00% 개선.**
     (expBY §9.5 상한 평균 2.67% 의 약 40% 실현을 요구한다.)

## 4. 위험

1. layer67 본문은 SLOTHY 가 **소프트웨어 파이프라인**한 코드다. 반복 간 의존이 있으므로
   ×8 펼침은 원래 루프와 같은 순서를 유지해야 한다. A 와 C 가 **같은 펼침**을 쓰므로
   비교는 성립하지만, **A 는 완전한 invNTT 가 아니다** — 메커니즘 증명용이다.
2. 병합 시 명령 순서를 바꾸므로 **NTT 내부 의존을 깨면 조용히 오답**이 난다.
   §2.4 의 출력 일치가 방어선이다.
3. `.text` 증가가 ITCM/flash 예산을 넘을 수 있다.
4. SLOTHY 주석의 "Expected cycles 48"은 **MVE 를 1/cyc 로 본 모델**이라 실제(92)와
   2배 다르다(expBZ). 그 주석을 근거로 쓰지 않는다.

## 5. 바꾸지 않는 것

invNTT 알고리즘, Keccak 정의, ML-KEM/X-Wing 정의, 현행 채택본(X06/X01/X02/K31).
CA-1 은 **측정용 커널만** 추가하며 제품 경로를 건드리지 않는다.
