같은 펌웨어의 A-pair까지 포함한 현재 최선과 비교
  1:1: 기존 951.040 -> T 1097.077 = 악화
  8:1: 기존 3012.029 -> T 2933.246 = 2.62% 개선
  4:1: 기존 1772.029 -> T 1865.065 = 5.25% 악화

분해
  레지스터 양보 제거: yield2 324.620 -> no-yield 273.040 = 15.89% 개선
  개더/스캐터 전환:  b2 754.053 -> b0 967.078 = 28.25% 악화
  단순 손익분기 근사: MVE 추가 213cyc / 곱당 회수 51.6cyc = 곱 약 4.1개.
  실제 스케줄 상호작용까지 넣으면 4:1은 손해, 8:1만 이득.

판정
  - 1:1: 악화.
  - 4:1(keygen/decaps): 악화 -> 기존 b2+yield2 유지.
  - 8:1(encaps): 작은 개선 -> b0+no-yield를 선택적으로 쓸 후보.
  - 하나의 전역 커널로 전 연산을 교체하면 안 된다. 연산 비율별 디스패치가 필요하다.
  - b0는 b2 명령을 기계 치환한 최초 스케줄이며 gather latency 3에 맞춘 재스케줄은 아직 안 함.
    따라서 967cyc는 현재 구현값이지 b0 설계의 최종 하한이 아니다.

재현성/민감도 메모
  이전 실험 S 전용 펌웨어의 8:1 A-pair 차이는 -0.60%였으나 이번 큰 펌웨어에서는
  +0.60%로 부호가 바뀌었다. 둘 다 사전등록의 ±1% '실질 차이 없음' 범위다.
  T의 8:1 개선은 현재 최선 대비 2.62%이고 두 번 정확히 재현되어 이 레이아웃 잡음보다 크다.
