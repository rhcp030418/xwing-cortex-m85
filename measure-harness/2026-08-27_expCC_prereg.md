# 사전등록 — 실험 CC: 벽인가 배치 문제인가 — **교차 종류별 겹침**

> 작성 2026-08-27, **측정 전**. expCB-② 의 직접 후속.

---

## 1. expCB 가 남긴 구멍

expCB-② 는 **같은 종류끼리만** 쟀다.

| 조합 | 실측 겹침 |
|---|---|
| MVE 적재 × 스칼라 적재 | **0%** |
| MVE 저장 × 스칼라 저장 | **−28.2%** (순차보다 느림) |
| MVE 연산(`vmul`) × 스칼라 연산(`umaal`) | **100%** (expBZ) |

**빠진 것: MVE 메모리 × 스칼라 연산, MVE 연산 × 스칼라 메모리.**

이것이 갈린다:

- **겹치면** → expCB 의 28% 손실은 **벽이 아니라 배치 문제**다.
  MVE 메모리 명령 옆에 스칼라 **연산**을 두도록 엮으면 회수된다.
- **안 겹치면** → 메모리 명령이 있는 한 상대 포트가 막히는 **구조적 벽**이다.

## 2. 커널 (각 128 명령, 버퍼 DTCM, `.text`)

| | 내용 |
|---|---|
| M | `vldrw` 64 + `umaal` 64 교대 — **MVE 적재 × 스칼라 연산** |
| N | `vmul` 64 + `ldr` 64 교대 — **MVE 연산 × 스칼라 적재** |
| O | `vstrw` 64 + `umaal` 64 교대 — **MVE 저장 × 스칼라 연산** |
| P | `vmul` 64 + `str` 64 교대 — **MVE 연산 × 스칼라 저장** |
| Q | `vldrw` 64 + `vmul` 64 교대 — MVE 내부 (적재·연산 서로 막는가) |

기준선은 expCB/expBZ 의 값을 쓴다: `vldrw` 410.56 · `vstrw` 410.69 · `vmul` 672.56 ·
`umaal` 544.56 · `ldr` 282.69 · `str` 220.56 (전부 128 명령 커널, 같은 오버헤드).

## 3. 판정 (gate 아님 — 메커니즘 측정)

expBA·expBZ·expCB 와 같은 **커널 간 차분**. 오버헤드 X 는 `umaal` = 1.000 으로 뽑는다.

```
작업량(mix) = max(작업량A/2, 작업량B/2)   ->  겹친다
작업량(mix) = 작업량A/2 + 작업량B/2       ->  안 겹친다
```

## 4. 이 결과가 정하는 것

- **M·O 가 겹친다** → 스티칭 상한이 살아난다. 병합 규칙을 "MVE 메모리 옆에는 스칼라
  연산"으로 바꾸는 **CC-2** 로 간다(같은 커널 쌍, 배치만 변경, 새 사전등록 없이
  아래 임계값으로 판정).
  - **CC-2 gate: 은닉률 ≥ 80%** (expCB-① 의 72.0% 대비 개선을 요구한다)
- **M·O 가 안 겹친다** → 메모리 명령이 상대 포트를 막는 **구조적 벽**이다.
  스티칭 상한을 **비-메모리 몫으로 다시 계산**하고 W03/W04/W05 를 그 값으로 판정한다.

## 5. 위험

1. `vstrw`/`str` 이 같은 DTCM 주소를 쓰면 write 충돌로 느려질 수 있다 →
   **서로 다른 오프셋**을 쓴다(expCB 와 같은 방식).
2. `.text` 배치 가정은 expCB 와 동일하게 유지한다(사전등록 §4-3).
