### 1.1 완성된 표 (expBZ + expCB + expCC)

| MVE 쪽 \ 스칼라 쪽 | 연산 | 적재 | 저장 |
|---|:-:|:-:|:-:|
| **연산** (`vmul`/`vadd`) | **100%** | **100%** | **100%** |

**MVE 저장이 그 성질을 스칼라 포트에까지 확장한다**는 것이 새로 밝혀진 부분이다.

## 2. CC-2 — 규칙을 배치에 넣었더니 **더 나빠졌다**

사전등록 §4 대로 병합 규칙을 고쳤다:
`vstrw` 슬롯 옆에는 스칼라를 두지 않고, `vldrw` 슬롯 옆에는 스칼라 적재를 두지 않는다.

| | 은닉률 | C |
|---|---:|---:|
| expCB-① 순진한 1:N 교대 | **72.0%** | 304.69 |
| **CC-2 규칙 배치** | **69.5%** | **310.62** |

**정확성은 두 판 모두 완전 통과**(ntt-mm 0, kec-mm 0).
**gate `CB-1a`(은닉률 ≥ 80%)는 두 배치 모두 FAIL, `CB-1b`(≥60%)는 PASS.**

### 2.1 왜 안 되는가 — 창이 애초에 모자란다

| | 값 |
|---|---:|
| MVE 포트 시간 (A) | 236.69 |
| 그중 `vstrw` 슬롯 (16개) | 약 **32** — 이 동안 스칼라 **불가** |
| **스칼라가 쓸 수 있는 창** | 약 **205** |
| Keccak 6 lane 이 필요한 스칼라 시간 (B) | **242.69** |

**필요(242.69) > 창(205).** 배치를 아무리 잘해도 남는 37 cyc 은 밖으로 나온다.
이론 최선 ≈ `242.69 + 32 = 274.7`, 실측 310.62 → 그보다 **13% 더**.

즉 CC-2 의 실패는 배치 규칙이 틀려서가 아니라 **여전히 lane 수를 크게 잡았기 때문**이다.
창 205 에 맞추려면 **5 lane 이하**여야 한다.

### 2.2 여기서 lane 수를 또 줄이지 않는다

expCA(8 lane) → expCB(6 lane) → CC-2(6 lane, 배치 변경) 로 세 번 재단했고
그때마다 gate 를 못 넘었다. **네 번째 재단은 gate 를 넘을 때까지 크기를 고르는 일**
(gate shopping)이 되므로 하지 않는다.

**판정: 부분 성공. 사전등록대로 CA-2(확대)로 가지 않는다.**

## 4. 스티칭 상한 재계산 (§1.1 규칙 적용)

이전 상한(expBY §9.5, 평균 2.67%)은 "스칼라 유휴 전부를 쓸 수 있다"고 봤다.
`vstrw` 가 스칼라를 막으므로 그만큼 빼야 한다.

`intt layer67` 기준: MVE 184 명령 중 **저장 16(8.7%)**.
저장이 차지하는 시간 비율만큼 창이 줄어든다.

```
보정 계수 ≈ 1 − (vstrw 시간 / MVE 총시간) ≈ 1 − 32/236.69 = 0.865
보정 상한 = 2.67% x 0.865 ≈ **2.31%** (세 연산 평균)
```

> 이는 **추정**이다. 다른 NTT 루프의 저장 비율은 따로 세지 않았다.

## 7. 정직 기록

1. **첫 회수기가 틀렸다.** expCB/expBZ/expCC 가 서로 **다른 프롤로그**를 쓰는데 한쪽의
   오버헤드를 다른 쪽에 적용해 작업량이 음수로 나왔다(겹침 3218% 등). 같은 프롤로그
   기준선 6종을 expCC 안에 넣어 자기완결로 고쳤다. **틀린 판은 인용하지 않는다.**
2. **CC-2 는 개선이 아니라 악화였다**(72.0% → 69.5%). 규칙이 틀린 게 아니라 창이
   모자란 것이었다(§2.1). 그래도 사전등록 gate 는 그대로 적용했다.
3. **lane 수를 네 번째로 줄이지 않았다**(§2.2). gate shopping 이 되기 때문이다.
4. 사전등록 §4 의 분기 조건("M·O 가 겹친다")은 **M 은 겹치고 O 는 안 겹치는**
   이번 결과를 예상하지 못했다. 조건이 불충분했음을 기록하고, 유리한 가지를 임의로
   고르지 않았다 — CC-2 를 돌리되 **사전에 고정된 gate(80%)로 판정**했다.
