# 실험 AM1 결과 — MVE field-mul feasibility gate

> 측정 2026-08-25. 사전등록 `2026-08-25_expAM1_mve_mul_prereg.md`, 설계
> `2026-08-25_expAM_x25519_mve_design.md`. 수정사항은 §9 amendment 참조.
> **판정: 정확성 전 게이트 PASS · 성능 기각(FAIL).** AM2 whole-ladder는 착수하지 않는다.

---

## 1. 한 줄 결론

MVE 열-스캐닝 field multiplication(B1)은 **정확하지만 scalar Lenngren 대비 2.0~2.2배
느리다.** 두 독립 run에서 전 슬롯 값이 **완전히 일치**했다. 사전등록 kill gate의
"5% 미만 또는 회귀 → AM1 실패로 종료"에 해당한다.

---

## 2. 대표 수치 — 실보드 실측

동일 ELF, N=100 중앙값, calib 25 차감, 배치 64 mul/span, ABBA, 독립 flash/run 2회.
**run1과 run2의 모든 슬롯 중앙값이 바이트 단위로 동일**하므로 아래 표는 두 run 공통이다.

### 2-1. field-mul 단가 (cyc/mul)

| 조건 | A = `fe25519_mul` (Lenngren 8×32, ITCM) | B1 = `fe25519_mul_mve` (MVE, ITCM) | 절감 |
|---|---:|---:|---:|
| 독립 피연산자 (AB / BA) | **158.50 / 158.50** | **346.50 / 346.50** | **−118.61%** |
| 의존 체인 (AB / BA) | **182.22 / 182.22** | **369.22 / 369.22** | **−102.62%** |

- ABBA 두 방향이 동일값이라 순서 효과 0이다.
- 판정 대상은 사전등록대로 **의존 체인**(ladder 의존성을 모사): **−102.62%**.

### 2-2. 명령 스루풋 마이크로 측정 (cyc/instruction)

`empty` 슬롯(호출 오버헤드 52 cyc)을 차감하고 64로 나눈 값이다.

| 슬롯 | 명령 | cyc/instr | 비고 |
|---:|---|---:|---|
| 341 | `vmlaldava.u32` ×64, 누산기 4쌍 순환 | **2.203** | 의존 없음 |
| 342 | `vmlaldava.u32` ×64, 누산기 1쌍 체인 | **2.125** | **의존 스톨 없음** |
| 343 | `vldrw.u32` ×64 | **2.047** | |
| 344 | `vmullb.u32` ×64 | **2.125** | |
| 345 | 스칼라 `umaal` ×64 | **1.188** | A의 코어 단가 |
| 346 | `vldrw` ×32 + 스칼라 `ldr` ×32 교대 | **1.562** | LSU 경합 확인용 |

**확정된 사실 3건:**

1. **M85의 MVE는 dual-beat다** — 128-bit 정수 연산이 일관되게 **약 2.05~2.20 cyc/명령**.
   AM0 §7-3의 "dual-beat 가정"이 실측으로 확인됐다(위험 M1 해소).
2. **같은 누산기 연속 `vmlaldava`에 의존 스톨이 없다** — 체인 2.125 < 독립 2.203.
   AM0 위험 M2는 **음성**이다. 오히려 체인이 근소하게 빠르다(레지스터 압박 차이로 보이며
   차이는 0.08 cyc/명령 = 미미).
3. **스칼라 로드는 MVE 로드와 듀얼이슈되지 않는다** — 교대 슬롯 실측 1.562 cyc/명령은
   순차 합산 예측 `(32×2.047 + 32×1.0)/64 = 1.523`과 사실상 일치하고, 완전 듀얼이슈
   예측 `≈1.02`와는 크게 다르다. **로드맵 40차 실측이 재현됐다**(위험 M3 확인).

### 2-3. 상수시간

`ct-delta = 0` — 서로 다른 두 비밀 피연산자 세트로 같은 64-mul 배치를 측정했을 때
사이클 차가 **0**이었다. 커널은 정적 disassembly에서도 **분기 0개**이며 모든 메모리
오프셋이 즉치 상수다.

## 4. 왜 졌는가 — 명령 클래스별 분해

측정된 단가로 B1의 282개 명령을 분해한다(**실측 단가 × 실측 명령 수**).

| 구간 | 명령 수 | 단가 | 소계 cyc |
|---|---:|---:|---:|
| `vmlaldava.u32` (열 내적) | 33 | 2.125 | **70.1** |
| `vldrw.u32` (슬라이스 로드 + 셋업) | 69 | 2.047 | **141.2** |
| `vstrw.32` | 7 | ~2.05 | 14.3 |
| `vmul.i32` / `vmov.i32` | 3 | ~2.1 | 6.4 |
| 스칼라 (접기 + carry 전파 + 셋업) | 170 | ~1.0~1.19 | **170~202** |
| 단순 합 (중첩 0 가정) | 282 | — | 402~434 |
| **실측** | | | **346.5** |

→ 중첩으로 약 **55~90 cyc**를 회수하고 있으나 여전히 A(158.5)의 2.2배다.

A의 분해(참고): 72 umaal × 1.188 = **85.5 cyc**, 나머지(로드/스토어/reduction/호출) **73 cyc**.

### 4-1. 핵심 기제 — radix 강등이 MAC 이득을 통째로 먹는다

| 항목 | A (8×32) | B1 (10×25.5) |
|---|---:|---:|
| 부분곱 수 | 64 | **100** (+56%) |
| MAC 명령 수 | 72 umaal | 33 `vmlaldava` |
| MAC 유효 처리율 | 0.84 MAC/cyc | **1.43 MAC/cyc** (1.70×) |
| **MAC 코어 소요** | **85.5 cyc** | **70.1 cyc** |
| MAC 코어 이득 | — | **겨우 15.4 cyc (18%)** |
| MAC 외 나머지 | 73 cyc | **276 cyc** |

**MVE의 MAC 처리율 우위 1.70배는, 작은 radix가 강제하는 부분곱 56% 증가에 거의 전부
잡아먹힌다.** 남은 15 cyc의 이득은 로드 트래픽(141 cyc)과 스칼라 carry 꼬리(~170 cyc)에
비하면 무의미하다.

### 4-2. radix를 낮출 수밖에 없는 이유 (근본 원인 사슬)

1. MVE의 유일한 광폭 MAC은 `vmlaldav*` 계열이고, **4 lane을 하나의 64-bit 스칼라 쌍으로
   환원**한다(설계문서 §5-3, QEMU 실측 확인).
2. lane별 독립 64-bit 누산기는 **존재하지 않는다**(`vmlalb.u32` 어셈블 거부).
3. **64-bit lane 산술 자체가 없다** — `vadd.i64`·`vshr.u64`·`vqmovnb.u64` 전부 거부.
   따라서 `vmullb/vmullt`의 64-bit lane 곱은 누산도 자리올림도 불가능하다.
4. ⇒ 열-스캐닝만 가능한데, 32-bit limb으로 열을 만들면 8항 × 2^64가 64-bit 누산기를
   넘친다. ⇒ **radix를 26-bit로 낮춰야 하고, limb이 8 → 10, 부분곱이 64 → 100이 된다.**
5. ⇒ 게다가 접기·carry 전파가 전부 스칼라로 남아 **170개 스칼라 명령**이 붙는다.

### 4-3. lane 활용률 / shuffle / spill / 배치 / ABI

| 요인 | 실측·정적 값 | 기여 |
|---|---|---|
| **lane 활용률** | `100 / (33×4)` = **75.8%** | 열 길이가 4의 배수가 아니라 완벽 패킹(25 명령) 불가. 손실 8 명령 ≈ 17 cyc |
| **로드 트래픽** | `vldrw` 69개 = **141.2 cyc** | **최대 단일 손실.** A의 전체 시간(158.5)에 육박 |
| **carry/접기(shuffle 대체)** | 스칼라 170개 ≈ **170~202 cyc** | 64-bit lane 산술 부재가 강제. 감축 여지 거의 없음 |
| **spill** | 없음 | 커널은 q0~q3만 쓰고 스택 프레임 264 B는 의도된 버퍼다. U의 spill 문제는 재현되지 않았다 |
| **code placement** | A·B1 **둘 다 ITCM** | 단일변수 유지. ITCM 59,760 → 62,480 B(+2,720), 여유 3,056 B. **퇴거 불필요** → 기존 슬롯 무교란 |
| **ABI 비용** | `push {r4-r11,lr}` 1회 | q4~q7 미사용이라 `vpush {d8-d15}` 없음. U의 +12~13% 양보 세금은 **발생하지 않았다** |

즉 **이번 패배는 U 때와 원인이 다르다.** U는 ABI 양보 세금과 spill이 주범이었지만,
B1은 그 둘을 모두 회피했는데도 **명령 클래스 자체의 산술**로 졌다.

## 5. 사전등록 대비 검증

### 5-1. Kill gate 적용

| 사전등록 조건 | 실측 | 판정 |
|---|---|---|
| ≥15% 절감, 두 run 부호 동일, 정확성 전부 통과 | −102.62% | 미충족 |
| 5~15% (보류, 1회 수정 후 재측정) | 해당 없음 | — |
| **5% 미만 또는 회귀** | **−102.62%** | **→ AM1 실패로 종료** |

사전등록 §7에 따라 **"정적 병목 1회 수정"은 적용하지 않는다.** 그 조항은 보류(5~15%)
구간 전용이며, 설계문서 §7-3이 예고한 로드 재사용 최적화(−24 `vldrw` ≈ −49 cyc)를
전부 적용해도 B1은 약 297 cyc로 A(182.22)의 1.63배에 머물러 gate에 도달할 수 없다.

### 5-2. 조기 종료 판정식 검산

사전등록 §3의 `FLOOR_B1 = 33·T_mac_dep + 50·T_vldrw + 135`:

```
FLOOR_B1        = 33×2.125 + 50×2.047 + 135 = 307.5 cyc
0.85 × A(체인)  = 0.85 × 182.22            = 154.9 cyc
307.5 > 154.9  → 조기 종료 조건 충족
```

**사전등록 판정식은 실측 346.5 cyc의 유효한 하한이었다(307.5 < 346.5).**
조기 종료를 적용했다면 커널 측정 없이 같은 결론에 도달했을 것이다.

> ⚠ **자진 신고**: 회수기가 함께 출력하는 "실제 명령 구성 기준" 값
> `33×2.125 + 79×2.047 + 170 = 401.8 cyc`는 **하한이 아니다.** MVE와 스칼라의 중첩을
> 0으로 가정해 단순 합산했기 때문에 실측 346.5를 **넘어선다**. 사전등록식(307.5)만
> 하한으로서 유효하며, 401.8은 "중첩 0 상한 추정"으로만 읽어야 한다. 판정에는 쓰지 않았다.

### 5-3. 사전 예측의 적중 여부

설계문서 §7-3의 예측은 "MVE 1 cyc/명령이면 282 cyc, 2 cyc/명령이면 394 cyc,
따라서 A의 173 cyc를 못 이긴다"였다.

- MVE 단가 실측 **≈2.1 cyc** → 예측 구간의 dual-beat 쪽이 맞았다.
- 예측 394 cyc 대 실측 **346.5 cyc** — 중첩분만큼 예측보다 빨랐으나 **결론(패배)은 적중**.
- A의 M4 저자 주석 173 cyc 대 M85 실측 **158.5 cyc** — M85가 M4보다 8% 빠르다.

## 6. 분모 명시

이 문서의 모든 %는 **field-mul 국소 %**다. X25519 종단간 %·X-Wing 종단간 %와 섞지 않는다.
표현 변환(8×32 ↔ 10×25/26) 비용은 **AM1 범위 밖**이며 측정하지 않았다(AM2용, 미측정).
B1이 회귀했으므로 종단간 투영은 **작성하지 않는다**.

**X-Wing 대표값은 변하지 않는다**: keygen 4.29% / encaps 4.16% / decaps 7.71%
(expAL, 2026-08-25). 이번 실험은 대표 경로 코드를 바꾸지 않았다 — B1은 ELF에 존재하지만
`curve25519_scalarmult`는 그대로 Lenngren `fe25519_mul`을 호출한다.

## 8. 실패·이탈·미측정 정직 기록

1. **QEMU 단계에서 커널 버그 1건 발생·수정**: 열 `k=18`(`i=j=9`, 둘 다 홀수 → ×2 보정
   필요)에 `A2BUF` 대신 `ABUF`를 쓴 오류. 단일-limb probe(100개 조합)가 정확히 짚어냈고
   보드 측정 전에 고쳤다. 보드에 올라간 것은 수정본이다.
2. **공유 `asm-practice/startup.s`가 CPACR을 켜지 않아** QEMU에서 MVE 명령이 UsageFault로
   무한루프에 빠졌다. 공유 파일을 고치지 않고 QEMU 진입점에서만 켰다.
3. **회수기의 "실제 명령 구성 기준 FLOOR"는 하한이 아니다** — §5-2 자진 신고 참조.
4. **미측정으로 남긴 것**:
   - 표현 변환(8×32 ↔ 10×25/26) 비용 — AM2용, B1 기각으로 불필요해짐
   - sqr 전용 MVE 커널 — 설계문서 §7-4에서 AM2 전제로 남겼으나 AM1 기각으로 미착수
   - 로드 재사용 최적화 적용본 — §5-1 사유로 미실시
   - `vmlaldava.u16`(8 lane) 경로 — AM0 §4에서 회계상 기각, 실측하지 않음
5. **ITCM 퇴거를 하지 않았다.** 여유가 충분해 불필요했고, 결과적으로 기존 슬롯이
   전혀 교란되지 않았다(AF2-P 판례 적용 대상 아님).
6. **A의 M85 단독 실측치 158.50 cyc/mul은 이번에 처음 측정한 값**이다. 기존 문서의
   173 cyc은 M4 저자 주석이며 실측이 아니었다.

## 9. 사전등록 대비 변경 (amendment)

사전등록 §2-3의 슬롯 정의를 다음과 같이 구체화했다. **측정 전에 확정했고 gate 임계값
(15% / 5%)과 판정 대상(묶음)은 바꾸지 않았다.**

| 사전등록 | 실제 구현 | 사유 |
|---|---|---|
| 333 A 단독 / 334 A+carry 묶음 / 335 B 단독 / 336 B+carry 묶음 | 333·336 = A 독립, 334·335 = B1 독립 (ABBA)<br>337·340 = A 의존 체인, 338·339 = B1 의존 체인 (ABBA) | A(8×32)와 B1(10×25.5) **둘 다 이미 완전 reduction을 포함**하므로 "mul + 별도 carry 묶음"이 성립하지 않는다. 대신 ladder의 실제 의존 구조를 모사하는 **의존 체인**을 묶음 대용으로 두고 이쪽을 판정 대상으로 삼았다 |
| 337~342 마이크로 6종 | 341~347 마이크로 7종 (`empty` 기준선 추가) | 호출 오버헤드 차감을 위해 기준선 슬롯 1개 추가 |
| `REP_SLOTS` 343 | **348** | 위 슬롯 증가분 반영. 회수기 `SLOT_N`도 348로 동기 |

배치 단위: 1 span = **64 mul**(단일 mul은 calib 25 cyc 대비 오차가 커서). 단가는
`(중앙값 − calib) / 64`.

## 10. 다음 단계 판단

- **AM2(whole-ladder)는 착수하지 않는다.** 사전등록 §8-5 "어느 경우든 AM2를 시작하지
  않는다"를 그대로 따른다.
- **AM3(X-Wing 통합)도 해당 없음.**
- 설계문서 §1의 정정(“`fe25519_mul`만으로는 종단간 6.1%가 상한”)과 이번 실측을 합치면,
  **M85 MVE로 X25519 field arithmetic을 가속하는 경로는 현재 ISA에서 닫혀 있다.**

  field arithmetic에서는 진다"**는 비대칭을 실측으로 뒷받침한다. 대표값 변경은 없다.
