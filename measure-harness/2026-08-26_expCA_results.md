# 실험 CA-1 결과 — **명령어 스티칭 실물 동작 확인**, 성능 gate 는 **부분 성공**

> 측정 2026-08-26. 보드 EK-RA8M1, DWT CYCCNT, REP_N=100, BATCH=16, ABBA, 독립 flash/run 2회 **동일**.
> 사전등록: `2026-08-26_expCA_stitch_prereg.md` §2.4 (측정 전 고정).
> 이 프로젝트의 본론이 **실물 커널에서 처음으로 동작한 기록**이다.

## 1. 판정

| 게이트 | 기준 | 실측 | 판정 |
|---|---|---:|---|
| **정확성** — C 의 NTT 출력 = A | mismatch 0 | **0** | **PASS** |
| **정확성** — C 의 Keccak 출력 = B | mismatch 0 | **0** | **PASS** |
| **CA-1a** | `C ≤ A × 1.05` (248.52) | **350.62** | **FAIL** |
| **CA-1b** | `C < A + B×0.5` (391.03) | **350.62** | **PASS** |

사전등록 §2.4: **"CA-1a 를 못 넘고 CA-1b 만 넘으면 부분 성공으로 기록하고 확대 단계로
가지 않는다."** → **부분 성공. CA-2(확대)로 가지 않는다.**

| 커널 | 명령 | cyc/호출 |
|---|---:|---:|
| **A** layer67 본문 ×4 (전부 MVE) | 184 | **236.69** |
| **B** Keccak extract lane ×8 (전부 스칼라) | 312 | **308.69** |
| **C** 병합 | 496 | **350.62** |

```
순차 실행이면  A + B = 545.38
실측 C                = 350.62
   ->  Keccak 308.69 cyc 중 **194.75 cyc(63.1%)가 공짜로 숨었다**
```

## 2. 가장 중요한 결과 — **병합 커널이 두 계산을 모두 정확히 한다**

496 명령짜리 병합 커널이

- invNTT layer67 버터플라이 4회분의 벡터 출력을 **A 와 바이트 완전 일치**로 내고
- Keccak 비트-인터리브 해제 8 lane 의 출력을 **B 와 바이트 완전 일치**로 낸다

**동시에** 해낸다. 레지스터 배정은 NTT 5개(`r7` `r11` `r8` `r9` `r12`) + Keccak 6개
(`r0` `r1` `r3` `r4` `r5` `r6`) = **11개 ≤ 14, 스필 0개**.

> 이 프로젝트가 3년 가까이 "스티칭"을 이야기했지만 **실제 PQC 커널 두 개를 엮어
> 양쪽 출력을 동시에 맞춘 것은 이번이 처음**이다. 이전 근거는 합성 proxy 였다.

## 3. 왜 100% 가 아닌가 — **내가 실험을 잘못 재단했다**

사전등록 §2.1 은 MVE 포트 시간을 `46 × 2 × 8 = 736 cyc` 로 잡았다.
expBZ 가 잰 **2.000 cyc/명령**을 그대로 적용한 값이다. 그런데 실측은:

```
A = 236.69 cyc / 184 MVE 명령 = **1.29 cyc/명령**
```

**expBZ 의 2.000 은 `vmul.i16 q,q,q` 한 종류에 대한 값**이었다.
NTT 의 실제 명령열은 `vldrw` · `vstrw` · `vmul` · `vqrdmulh` · `vmla` · `vadd` · `vsub`
혼합이며 **평균 1.29 cyc/명령**으로 훨씬 빠르다.

그래서 두 포트의 크기가 사전등록 가정과 뒤집혔다:

| | 사전등록 가정 | **실측** |
|---|---:|---:|
| MVE 포트 (A) | 736 | **236.69** |
| 스칼라 포트 (B) | 567 | **308.69** |
| 어느 쪽이 큰가 | MVE | **스칼라** |

**스칼라가 더 크므로 이론상 최선은 `A` 가 아니라 `max(A,B) = B = 308.69` 다.**

```
이론 최선 308.69  /  실측 350.62   ->  이론값의 **88%**
```

즉 **메커니즘은 88% 효율로 작동**했고, `C ≤ A×1.05` 라는 gate 는 **A 가 더 클 것이라는
내 가정 위에 세운 잘못된 기준**이었다. 8 lane 을 고른 것도 같은 잘못된 모델에서 나왔다
(736 cyc 안에 넣으려 했는데 실제 여유는 236 cyc 였다).

> **gate 를 고치지 않는다.** 사전등록은 사전등록이고, CA-1a 는 FAIL 이다.
> 다시 하려면 **새 사전등록**으로 lane 수를 A 아래로 잡아야 한다(§5).

## 4. 남은 41.93 cyc 의 정체 — 미규명

```
실측 350.62 − 이론 최선 308.69 = 41.93 cyc  (12.0%)
```

후보(전부 **미측정**):

1. 병합 비율이 고정(1 MVE : 1.7 스칼라)이라 구간에 따라 한쪽이 굶는다.
2. Keccak 의 `str` 2개/lane 이 발행을 차단한다(expBA) — 8 lane × 2 = 16 cyc.
3. NTT 의 `vldrw`/`vstrw` 와 Keccak 의 `ldrd`/`str` 이 **같은 메모리 포트**를 다툰다.
   expBV 커널 F 가 이 방향을 시사했으나 그 측정은 `.bss` 탓에 무효였다.
4. 병합 커널 496 명령의 명령 캐시·정렬 효과.

**3번이 가장 유력하다** — expBZ 는 `vmul`(메모리 미접촉)로만 100% 겹침을 확인했고,
**메모리를 건드리는 MVE 와 스칼라가 함께 있을 때는 재지 않았다.**

## 5. 다음 (새 사전등록 필요)

1. **lane 수를 A 아래로**: 236.69 / 38.59 = **6 lane** 이하. 그러면 이론 최선이 A 가 되고
   `C ≈ A` 를 물을 수 있다.
2. **메모리 포트 경합 측정**: `vldrw`(DTCM) × `ldr`(DTCM) 교차 커널. expBV F 의 재실험.
3. 그 뒤에 CA-2(확대 — `fe25519_mul` 로 교체, full X-Wing A/B).

## 9. 정직 기록

1. **CA-1a FAIL 은 메커니즘 실패가 아니라 내 재단 실패다**(§3). 그래도 gate 는 낮추지 않고
   사전등록대로 "부분 성공, 확대 안 함"으로 판정했다.
2. **expBZ 의 MVE 2.000 cyc/명령을 모든 MVE 에 일반화한 것이 틀렸다.** 실제 NTT 혼합
   명령열은 **1.29** 다. expBZ 문서에 정정 주석을 단다.
3. §3 의 "이론값의 88%"는 사후 계산이며 **사전등록된 기준이 아니다.** 판정에 쓰지 않았다.
4. ITCM/DTCM 초과로 다른 실험 커널의 배치를 바꿨다(§6). 그 실험들을 재실행하면 값이 달라진다.
