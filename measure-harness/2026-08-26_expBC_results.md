# 실험 BC (BB-2) 결과 — X02 재스케줄 sqr 을 full X-Wing 에: **gate PASS**

> 측정 2026-08-26. 보드 EK-RA8M1, DWT CYCCNT, REP_N=100, 같은 ELF ABBA, 독립 flash/run 2회.
> 사전등록: `2026-08-26_expBB_x02_reschedule_prereg.md` §3.2.
> 선행: expBB(micro +14.80%), expAX(X06 최종).

## 2. gate 해석 정정

첫 회수기는 AT-3(X06)용을 그대로 복사해 **"decaps 는 ±0.3% 이내"** 조건을 걸었고
decaps 가 +2.23% 개선되자 FAIL 을 냈다. **그 조건은 X06 전용이다** — X06 은 decaps 에
적용 지점이 없어 변화가 곧 배치 교란 신호였다. **X02 는 `fe25519_sqr` 이므로 ladder 를
쓰는 세 연산 모두에 적용 지점이 있다.** BB 사전등록 §3.2 의 실제 조건은
"full X-Wing 에서 하나라도 회귀하면 채택 금지"뿐이며, 그 기준으로 **PASS** 다.

회수기의 gate 의미만 고쳤고 **임계값을 낮추지 않았다.**

## 3. micro 대비 감쇠 — 70%

| | sqr 호출 수 | 절감 총량 | 호출당 |
|---|---:|---:|---:|
| keygen | 254 | 3,968 | 15.6 |
| encaps | 1,528 | 23,290 | 15.2 |
| decaps | 1,274 | 19,289 | 15.1 |

micro A/B 는 21.7 cyc/호출이었는데 full 에서는 **15.1~15.6** 으로, **약 70% 만
회수**된다. 세 연산에서 호출당 값이 일치하므로 우연이 아니다.

원인은 **미규명**이다. 후보:

1. micro 벤치는 같은 입력을 64회 반복해 D-cache·분기예측이 이상적이지만, ladder 는
   매번 다른 값과 다른 호출 문맥을 준다.
2. `fe25519_sqr_many` 의 타이트 루프에서 재배치된 명령열이 다르게 상호작용한다.
3. micro 는 AAPCS shim 을 통과하는데 ladder 는 native 호출이라 앞뒤 문맥이 다르다.

**투영(§BB 3: keygen −0.86% / encaps −3.28% / decaps −3.41%)보다 낮다.** 투영은
21.7 cyc/호출을 그대로 곱한 값이었고, 실제 감쇠를 반영하지 못했다. 앞으로 micro 단가를
full 로 외삽할 때 **70% 감쇠**를 기억한다.

## 4. 디스패처

`fe25519_sqr` 심볼을 얇은 디스패처(`gen/x02_dispatch.S`)가 갖고 `x02_mode` 로 갈라진다.
`fe25519_mul/add/sub` 는 같은 파일에서 `apx_real_*` 로 단순 tail-branch 한다.
**양쪽 경로가 같은 진입 비용을 물므로 A/B 차분에 영향이 없다.**

다만 디스패처 자체가 총합을 올린다 — A 셀 keygen 644,240 은 expAX 의 640,278 대비
+4,000 정도다(sqr 호출당 ~4 cyc + 배치 변화). **채택 시에는 디스패처를 걷어내고
`fe25519_sqr` 를 재스케줄본으로 직접 대체해야 하며, 그때 다시 재야 한다.**
