# 실험 BM 결과 — X01-v2 `fe25519_mul` 프레임 평탄화: **BM-B1 미달로 X01 종료**

> 측정 2026-08-26. 보드 EK-RA8M1, DWT CYCCNT, REP_N=100, BATCH=64, 같은 ELF ABBA, 독립 flash/run 2회 **동일**.
> 사전등록: `2026-08-26_expBM_x01v2_flatframe_prereg.md` §3 (측정 전 고정).
> 선행: expBD(X01 1차 +3.81% < 5%), expBB(X02 sqr +14.80%), expBJ(측정 배치 규율).

---

## 1. 판정

| 게이트 | 기준 | 실측 | 판정 |
|---|---|---:|---|
| **BM-A** 평탄화본 중립성 | −1.0% ~ **+3.0%** | **+3.82%** (창 밖, **유리한 쪽**) | **FAIL** |
| **BM-B1** 재스케줄 절감 | ≥ 8.0% | **+2.65%** | **FAIL** |
| 정확성 (경계 49 + 무작위 1,000) | mismatch 0 | **flat-mm 0 / sched-mm 0 / 1,049 검사** | PASS |
| 명령 수 불변 | 필수 | 120 → 120 → 120 | PASS |

사전등록 §3.2: **"셋 다 넘어야 채택한다. 못 넘으면 X01 을 완전히 종료한다."**
→ **X01 을 종료한다. gate 를 낮추지 않는다.**

| | cyc/호출 (두 판 동일) |
|---|---:|
| 원본 `fe25519_mul` | **156.94** |
| 평탄화본 `fe25519_mul_flat` | **150.94** |
| 재스케줄본 `fe25519_mul_sched` | **146.94** |

원본 156.94 는 expBD 의 157.36 과 일치한다(다른 빌드, 0.27% 차).

## 2. BM-A 는 **유리한 쪽으로** 창을 벗어났다 — 창을 잘못 잡은 것이다

사전등록은 "명령 수·메모리 워드 수가 같으니 중립이어야 한다"고 보고 −1.0~+3.0% 창을
걸었다. 실측은 **+3.82% 빠르다.**

원인은 명확하다: `push`/`pop` 은 **sp 를 갱신**하므로 뒤따르는 모든 sp 상대 접근이
그 갱신에 의존한다. 고정 오프셋 `str`/`ldr` 에는 그 의존이 없다.
바꾼 sp 조작 4개(`push{r6,r7}`, `push{r0}`, `pop{r11}`, `pop{r0-r2}`/`pop{r3,r4}`/`pop{r5,r6}`)
에서 **6 cyc** 이 빠졌다.

**즉 창을 −1.0~+3.0% 로 잡은 내 가정이 틀렸다.** 변환이 뭔가 망가뜨린 것이 아니라,
sp 의존 사슬을 제거한 것이 그 자체로 이득이었다. **그래도 사전등록은 사전등록이므로
이 실험에서 BM-B 로 넘어가지 않는다고 기록한다** — 다만 BM-B 수치는 같은 판에서
이미 나왔고(§1), 그것도 **8% 요구에 2.65% 로 미달**이므로 결론은 어느 쪽이든 같다.

## 3. 재스케줄이 왜 2.65% 뿐인가 — 모델이 baseline 을 재현하지 못했다

| | 모델 | 실측 |
|---|---:|---:|
| 평탄화본 블록(116 명령) | **145.0** | 본문 약 **105** (150.94 − 고정점 약 46) |
| 재정렬 후 | 133.0 (−8.3%) | 본문 약 **101** (−3.8%) |

**모델이 baseline 을 38% 과대평가한다.** 규칙 5 는 이 경우 "그 스케줄을 보드에 올리지
않는다"고 정한다. 이 실험은 BM-A/BM-B 를 같은 빌드에 넣어 한 번에 쟀기 때문에
**결과적으로 규칙 5 를 지키지 못했다**(§7-2 정직 기록).

expBD §2.1 이 이미 같은 현상을 보고했다(전 함수 모델 151 vs 실측 111).
**평탄화로 push/pop 을 없애도 과대평가는 남았다** — 원인은 push/pop 폭이 아니라
다른 데 있다. `latency()` 가 곱셈 결과를 누산기 외에는 2 로 잡는데,
`umaal` 사슬이 대부분인 이 커널에서 그 값이 과한 것으로 **추정**된다. **미측정**이다.

## 4. 그래도 남은 사실 — 합계 **+6.37%**

```
원본 156.94  ->  평탄화+재스케줄 146.94   =  +6.37%
```

정확성은 **경계 49 + 무작위 1,000, limb 단위 mismatch 0** 으로 완전 검증됐고
명령 수도 불변이다. **이 6.37% 는 expBD 가 닫은 X01 1차 gate(5%)를 넘는다.**

그러나:

1. expBD 의 gate 는 **이미 닫혔다.** 되살리지 않는다(규칙 3).
2. BM 의 gate 는 **못 넘었다.** 낮추지 않는다.
3. **full X-Wing 에서의 효과는 아직 재지 않았다 — 미측정이다.**

따라서 `fe25519_mul_sched` 를 채택하려면 **full X-Wing 통합 효과에 대한 새 사전등록**이
필요하다. micro 는 알려졌지만 통합 결과는 모른다(expBC 는 micro 21.7 cyc/호출이 full 에서
15.1~15.6 으로 **70% 만** 회수되는 것을 보였다). → **expBN**.

## 6. 미측정·한계

1. **모델 과대평가의 원인 미규명**(§3). `umaal` 결과 지연 2 가 과한지 별도 측정이 필요하다.
2. full X-Wing 통합 효과 **미측정**(§4).
3. 스택 high-water **미측정**.
4. `fe25519_sqr` 에는 sp 조작이 없어 이 수법이 적용되지 않는다.
5. EK-RA8M1 한 개체, 이 배치 한정.

## 7. 정직 기록

1. **첫 측정판은 무효였다.** `expbm_a/b/r*` 를 `.bss` 에 두어 단가가 397.38 로 나왔다
   (실제 156.94의 2.5배). **expBJ §1 에서 방금 세운 규율을 바로 다음 실험에서 어겼다.**
   버퍼를 DTCM 스택으로 옮겨 다시 쟀고, 무효 판의 수치는 판정에 쓰지 않았다.
   (참고: 그 무효 판에서도 BM-A +2.01%, BM-B +1.04% 로 방향은 같았다.)
2. **규칙 5 를 지키지 못했다.** BM-A 와 BM-B 를 같은 빌드에 넣어 한 번에 쟀기 때문에,
   모델이 baseline 재현에 실패했음을 확인하기 **전에** 재스케줄본이 이미 보드에 올라가 있었다.
   앞으로는 모델 검증이 필요한 실험에서 **단계를 빌드로 분리**한다.
3. **BM-A 의 창(−1.0~+3.0%)은 내 가정이 틀린 것**이며(§2), 실측은 유리한 쪽으로 벗어났다.
   그 사실을 근거로 창을 넓히지 않았다.
4. §4 의 +6.37% 는 **micro 실측**이며 full X-Wing 절감률이 아니다.
