# 분석 BT — K20/K21(Keccak 배칭) 상한: **종료**

> 2026-08-26. **실측 재계산**이다. 입력: expBS(x4 통합 실측), 장부의 4-way MVE Keccak
> 상각 절감률 18.13%, expBJ(permutation 5,505.81), expAQ(XOF 배관), expAO(Keccak 분모).

---

## 1. 핵심 산술 — 4-lane 기계에 3-wide 작업

ML-KEM-768 의 matrix-XOF 는 **행마다 3개**의 독립 SHAKE 스트림을 쓴다.
MVE 는 **4-lane** 이다. 현행 x4 경로는 **3 + dummy 1** 로 채운다.

장부의 4-way MVE Keccak 실측: **상태당 상각 절감 18.13%**.

```
4-way 로 4 상태     : 4 x 5,505.81 x (1 - 0.1813) = 18,033 cyc
스칼라로 3 상태     : 3 x 5,505.81                =  16,517 cyc
                                       차이 = +1,516 cyc  (x4 가 더 비싸다)
```

**dummy lane 1개(33% 낭비)가 18.13% 절감을 그대로 삼킨다.**
행 3개 × (absorb + 초기 squeeze) 에 이를 적용하면 수 kcyc 의 순손실이며,
여기에 상태 복사·`extseed` 구성이 더해진다.

**expBS 가 이것을 보드에서 확인했다: keygen −2.98% / encaps −2.03% / decaps −2.45%.**

## 2. "true x3" 은 해법이 아니다

장부는 K21 을 "true x3 또는 개선된 x4"로 적었다. 그러나 **MVE 는 4-lane 이므로
x3 을 돌려도 lane 하나는 놀고, 비용은 x4 와 같다.** dummy 를 "쓰지 않는" 것과
"lane 이 노는" 것은 하드웨어 관점에서 같다.

2-way 로 낮추면 lane 낭비가 50% 로 **더 나빠진다.**

## 3. 유일하게 남는 변형 — 행을 가로질러 배칭

연산당 XOF 스트림은 **9개**(3행 × 3열)다. 행 단위가 아니라 **9개를 가로질러** 묶으면
`4 + 4 + 1` 로 dummy 없이 8개를 채울 수 있다.

```
8 스트림 x4 로   : 2 x 18,033 = 36,066
8 스트림 스칼라  : 8 x 5,505.81 = 44,046
                            상한 절감 = 7,980 cyc / 연산
   keygen 1.28% / encaps 0.82% / decaps 1.02%   (평균 1.04%)
```

**상한이 expBP §0 기준(1.0%)에 겨우 걸친다.** 그런데:

1. 이 변형은 **9개 스트림의 첫 블록을 미리 다 만들어 두어야** 한다
   → 9 × 168 B = **1,512 B 버퍼** + 9개 상태(1,800 B)를 동시에 유지.
2. matacc 는 행을 **순차 소비**하므로 구조를 크게 바꿔야 한다.
3. **expBS 가 실측한 배관 부대비용은 +19~20 kcyc/연산**이다. 위 상한 7,980 은 그 절반도
   안 된다. 버퍼가 더 커지는 변형이 그 배관을 오히려 늘리지 않을 이유가 없다.

**→ 상한(7,980)보다 이미 실측된 배관 부대비용(19,800)이 2.5배 크다. 종료한다.**

## 4. K20(MVE permutation 자체 재작성)도 같은 벽에 막힌다

K20 은 "true 2-way MVE Keccak" 이다. 두 가지 이유로 상한이 낮다.

### 4.1 M85 에서 스칼라 회전은 **공짜**다 (expBL 실측)

expBL 규칙 1: `eor rD, rN, rM, LSR #k` 는 평 `eor` 과 **처리율·지연이 완전히 동일**하다.
스칼라 Keccak 의 rho 회전은 전부 shifted operand 로 접혀 **명령 수 0** 이다
(expBE §2: 몸통 1,526 명령에 회전 명령이 따로 없다).

**MVE 에는 벡터 회전이 없다.** `VSHL` + `VSHR` + `VORR` 3개가 필요하다.
Keccak 라운드마다 회전이 약 29개 → 4 라운드당 **+232 명령**.

### 4.2 스칼라 Keccak 은 이미 IPC 1.66 으로 발행 한계 근처다

expBE: 몸통 1,526 명령 / 917.3 cyc, store 차단 반영 하한 875.5 → **여지 4.6%**.

2-way MVE 가 이기려면 (1,526 + 232) / 2 = 879 MVE 명령이 **917 cyc 안에** 들어와야 한다
= MVE 명령당 1.04 cyc. 128-bit MVE 정수 연산은 일반적으로 2-beat 이므로
**dual-beat 겹침이 완벽해야 겨우 본전**이다. 게다가 2-way 는 4-lane 중 2개만 쓴다.

**→ K20 도 종료한다.**

## 5. 판정

| 가족 | 판정 | 근거 |
|---|---|---|
| **K21** matrix-XOF 배칭 | **종료** | expBS 보드 실측 −2.0~−3.0%; dummy lane 이 18.13% 를 삼킴(§1); 행 교차 변형도 상한 < 실측 배관비용(§3) |
| **K20** MVE 2-way permutation | **종료** | 스칼라 회전이 공짜(expBL §3-1)이고 스칼라 Keccak 이 이미 IPC 1.66(expBE) — MVE 는 회전에 3배 명령이 든다(§4) |

## 6. 미측정·한계

1. §4.1 의 "라운드당 회전 약 29개"는 Keccak 정의에서 센 것이며, 실제 MVE 구현의
   명령 수는 **미측정**이다.
2. MVE 명령의 M85 발행 비용을 **직접 재지 않았다**(expBA/expBL 은 스칼라만 쟀다).
   §4.2 의 "2-beat" 는 문헌 가정이다.
3. §1 의 18.13% 는 장부에 기록된 과거 측정이며 이 세션에서 재검증하지 않았다.
4. §3 의 행 교차 배칭은 **구현·측정하지 않았다.** 상한과 기존 배관 실측의 비교로 판단했다.
5. EK-RA8M1 한 개체, 이 배치 한정.
