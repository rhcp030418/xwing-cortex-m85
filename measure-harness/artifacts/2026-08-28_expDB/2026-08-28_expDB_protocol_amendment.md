# expDB 프로토콜 보정 기록

> 2026-08-28, phase-1의 첫 solver 시도가 입력 파싱에서 중단된 뒤, 후보 생성과 보드 측정 전에 기록.

## 발생 사실

`p1_raw.s`의 무자료형 별칭 `vorr qD, qN, qN`을 현재 SLOTHY Armv8.1-M 파서가 받지 못해 solver가 최적화 전에 종료했다. 실패 원로그는 `slothy-2stream/expDB/p1_solver_parse_failure.log`로 보존한다.

## 보정

입력 생성 단계에서 해당 별칭만 `vorr.i32 qD, qN, qN`으로 바꾼다. 두 표기는 Arm 어셈블러에서 같은 128-bit OR 연산이며, 피연산자와 순서를 바꾸지 않는다. solver 옵션, 허용 레지스터, 목적함수, 시간 제한, 보드 판정 기준은 변경하지 않는다.

## 해석 제한

이 보정은 사전등록 후 발생했으므로 최종 결과에 프로토콜 보정으로 명시한다. 파싱 실패 시도는 성능 표본으로 세지 않는다.

## 별칭 안전성 보정

첫 전체 보드 실행에서 `KAT ALL PASS`였지만 expDB 전용 mismatch가 12,800으로 정확성 게이트를 실패했다. phase별 진단에서 비별칭 필드 곱셈 출력과 전체 MVE 상태는 모두 원본과 일치했고, 출력이 입력과 겹칠 때만 solver본이 틀렸다. 변환 원순서 대조군 `Ut`는 별칭 조건에서도 일치했다. 원인은 SLOTHY가 `r0`, `r1`, `r2`가 가리키는 메모리의 상호 별칭을 모델링하지 않아, solver가 출력 store를 아직 필요한 입력 load보다 앞당긴 것이다.

실제 ladder가 요구하는 별칭 계약을 보존하기 위해 두 10-limb 입력을 각각 지역 배열에 복사하고 solver본을 호출하는 래퍼 `fiat_mul_u4a_p0..p3`를 후보에 추가한다. 처음에는 `out == a || out == b`인 경우에만 복사했으나 전체 보드 게이트에서 같은 12,800 mismatch가 재현되어 이 후보도 폐기했다. 실제 버퍼 관계가 단순 포인터 동일성보다 넓음을 확인했으므로 최종 보정 후보는 두 입력을 **항상** 복사한다. 이 보정의 복사·추가 호출 비용을 포함한 값을 후보 성능으로 측정한다. 실패한 후보들의 성능 수치는 폐기하며, 보정 후보는 새 ELF로 독립 flash 2회를 다시 수행한다.
