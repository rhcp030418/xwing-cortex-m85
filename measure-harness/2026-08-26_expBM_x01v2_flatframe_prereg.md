# 사전등록 — 실험 BM (X01-v2): `fe25519_mul` 프레임 평탄화 후 재스케줄

> 작성 2026-08-26, **측정 전**. 장부 ID **X01**의 **두 번째 접근**.
> X01 1차(expBD)는 순수 재정렬로 +3.81% < 5% gate 에 걸려 종료됐다.
> **이 문서는 그 gate 를 되살리지 않는다 — 새 접근·새 임계값이다**(규칙 3).

---

## 1. 분모와 1차 실패 원인 (실측)

| | 값 |
|---|---:|
| `fe25519_mul` 단가 | **157.36 cyc** (expBD §1) |
| 명령 / 곱셈 / store 워드 | 120 / 73 / 12 |
| expBA·expBL 발행 모델 하한 | 73 + 12 = **85** |
| 본문 실측 | 약 111 |
| **여지** | **약 23.4%** |
| encaps 중 `fe25519_mul` 비중 | **26.1%** (expAN) |

expBD §2 가 확정한 실패 원인은 알고리즘이 아니라 **커널 구조**다:

> `fe25519_mul` 은 본문 중간에 `push {r6,r7}` / `push {r0}` / `pop {r11}` 을 끼워
> 레지스터를 늘려 쓴다. 이 sp 조작들이 **재정렬 가능 구간을 3개로 조각낸다.**

sqr 은 71 명령이 한 덩어리라 +14.80% 가 나왔다(expBB).

## 2. 방법 — 프레임을 고정하고 push/pop 을 같은 비용의 str/ldr 로 바꾼다

중간 `push`/`pop` 은 **레지스터가 모자라 스택을 임시 슬롯으로 쓰는 것**이다.
프레임을 미리 크게 잡아 두면 sp 를 움직이지 않고 같은 일을 할 수 있다.

`sub sp,#28` → **`sub sp,#40`** 으로 바꾸면 진입 sp 를 E 라 할 때 본문 내내 **sp = E−48 고정**이다.

| 원본 | 평탄화본 | 명령 수 | 메모리 워드 |
|---|---|:-:|:-:|
| `push {r6,r7}` | `strd r6,r7,[sp,#0]` | 1→1 | 2→2 |
| `strd r8,r9,[sp,#8]` | `strd r8,r9,[sp,#8]` (불변) | 1→1 | 2→2 |
| `str r11,[sp,#16+4]` 외 4개 | `[sp,#16]`,`#20`,`#24`,`#28`,`#32` | 5→5 | 5→5 |
| `push {r0}` | `str r0,[sp,#36]` | 1→1 | 1→1 |
| `ldr r2,[sp,#40]` | 불변 | 1→1 | 1→1 |
| `pop {r11}` | `ldr r11,[sp,#36]` | 1→1 | 1→1 |
| `ldrd r4,r5,[sp,#28]` | 불변 | 1→1 | 2→2 |
| `pop {r0-r2}` | `ldm sp,{r0,r1,r2}` | 1→1 | 3→3 |
| `pop {r3,r4}` | `ldrd r3,r4,[sp,#12]` | 1→1 | 2→2 |
| `pop {r5,r6}` | `ldrd r5,r6,[sp,#20]` | 1→1 | 2→2 |
| `add sp,#12` | `add sp,#44` | 1→1 | 0→0 |

**명령 수와 메모리 워드 수가 하나도 바뀌지 않는다.** 프레임 슬롯 배치만 바뀐다:

```
[sp,#0]  r6     [sp,#16] 저장1   [sp,#32] 저장5
[sp,#4]  r7     [sp,#20] 저장2   [sp,#36] r0 임시
[sp,#8]  r8     [sp,#24] 저장3   [sp,#40] 저장된 r2 (인자)
[sp,#12] r9     [sp,#28] 저장4   [sp,#44] lr
```

이 배치는 `ldm sp,{r0,r1,r2}` 와 `ldrd` 세 개가 **원본 `pop` 이 읽던 값을 그대로**
읽도록 고른 것이다.

그 결과 `sub sp` 와 `add sp` 사이 **본문 전체가 하나의 재정렬 가능 블록**이 된다.

## 3. 두 단계로 나눠 판정한다

### 3.1 BM-A: 평탄화본 자체 (재정렬 없음)

- **정확성**: 경계 7 + 무작위 1,000 벡터에서 원본과 **limb 단위 완전 일치**
- **성능**: 원본 대비 **−1.0% ~ +3.0%** 안에 들 것
  (같은 명령·같은 메모리 워드이므로 중립이어야 한다. 벗어나면 변환이 뭔가 바꾼 것이다.)

**BM-A 를 통과하지 못하면 재스케줄로 넘어가지 않는다.**

### 3.2 BM-B: 평탄화본을 단일 블록으로 재스케줄

- **모델 검증(규칙 5)**: 스케줄러 모델의 baseline 이 평탄화본 실측을 재현해야 한다.
  **재현 실패 시 그 스케줄을 보드에 올리지 않는다.**
- **BM-B1: micro 단가 ≥ 8.0% 절감** (평탄화본 대비).
- **BM-B2: full X-Wing 세 연산 중 하나라도 회귀하면 채택 금지.**
- **BM-B3: encaps 에서 ≥ 1.5% 개선.**
  (근거: mul 은 encaps 의 26.1%. 8% 절감이면 2.1%, expBC 의 micro→full 감쇠 70% 를
  적용해도 1.5%.)

셋 다 넘어야 채택한다. 못 넘으면 **X01 을 완전히 종료한다.**

### 3.3 정확성 (BM-B 에도 동일 적용)

- 경계 7 + 무작위 1,000 벡터 limb 일치
- **명령 수 불변** (평탄화본 대비). 바뀌면 도구 버그로 본다(규칙 9).
- full X-Wing 8-seed 바이트 동일 + 암묵적 거부 동일, RFC 7748 KAT, `harness_fails = 0`

## 4. 위험

1. **프레임 오프셋을 하나라도 잘못 옮기면 조용히 오답**이 난다 → §3.1 의 1,000 벡터가 방어선.
2. `ldm sp,{r0,r1,r2}` 는 sp 를 갱신하지 않는 형태여야 한다(`ldm sp!` 아님).
3. 프레임이 12 B 커진다(스택 high-water +12). 보고한다.
4. 재스케줄이 `[sp,#k]` 메모리 의존을 잘못 다루면 오답 → 도구는 `[sp,#k]` 를 이미
   메모리 의존으로 모델링한다(expBB). 그래도 §3.3 이 방어선이다.
5. 이 커널은 `*r1=a, *r2=b` 커스텀 ABI 다. **입출력 레지스터 규약은 건드리지 않는다.**

## 5. 바꾸지 않는 것

곱셈 알고리즘(8×8 schoolbook + 38-reduction), 커스텀 ABI, `fe25519_sqr`(이미 채택),
`fe25519_add/sub`, X25519 ladder, ML-KEM/X-Wing 정의.
