# 설계 — 실험 CG: **게스트 재물질화 할당** (스티칭 통합용)

> 작성 2026-08-27. **설계 문서**이며 구현·측정 전이다. 사전등록(§7)은 구현 전에 고정한다.
> 선행: expCF(레지스터 5개 부족, `vdup` 경로 닫힘), expCE(누출 0.34 cyc/명령, 종류 무관).

---

## 0. 한 줄 요약

**호스트(X25519 커널)는 한 명령도 바꾸지 않는다.** 게스트(NTT layer67)의 스칼라 요구를
"항상 살아 있는 5개"에서 "**MVE 명령 하나가 발행되는 순간 죽어 있는 1개**"로 바꾼다.
그 1개는 호스트의 라이브니스에서 고르고, 필요한 값(상수·베이스)은 그 자리에서
`movw`/`movt` 로 **재물질화**한다. 메모리도, 스택 슬롯도, 호스트 재할당도 없다.

## 1. 문제 재정의 — 왜 "스필 5개"가 틀린 틀인가

expCF 는 부족분을 5개로 셌다: NTT 5 + mul 14 = 19 > 14. 이 셈은 **두 스트림이 각자의
레지스터를 내내 점유한다**고 본 것이다. 실측으로 확인한 사실은 다르다.

| 사실 | 값 | 출처 |
|---|---|---|
| mul 은 본문 내내 14개가 거의 다 산다 (최대 동시 live 14, 각 레지스터 90%+) | 스필로 5개를 빼면 **매 사용마다 재적재**해야 하고 그 임시 레지스터가 없다 | `mul_liveness.py` |
| NTT 의 스칼라 5개 중 **3개는 루프 불변 상수** (`r12=−3329`, `r8`·`r9` root) | `movw` 1명령으로 재생성 가능, **메모리 불필요** | 원본 소스 |
| 나머지 2개는 **포인터** (`r11` 적재, `r7` 저장) | 펼친 몸통에서는 `base + imm` (vldrw imm ±508, 4 iter × 96 = 384 ✓) | `design_inputs.py` |
| **MVE 명령 하나가 필요로 하는 스칼라 레지스터는 최대 1개** | 46개 중 16 불필요 · 16 상수 · 10 적재포인터 · 4 저장포인터 | `design_inputs.py` |

→ 물어야 할 것은 "5개가 비는가"가 아니라 **"삽입 지점마다 1개가 비는가"** 다.

## 2. 측정 입력 — 호스트의 빈 레지스터 분포

호스트 본문의 각 삽입 지점(명령 `i` 뒤)에서 `REGS − live_after[i]` 를 셌다.

| 호스트 | 본문 | free ≥ 1 인 지점 | free ≥ 2 | free ≥ 3 | free = 0 | 최장 연속(≥1) |
|---|---:|---:|---:|---:|---:|---:|
| `fe25519_mul_sched` (X01 채택본) | 116 | **60.3%** (70) | 31.0% | 19.8% | **39.7%** (46) | 16 |
| `fe25519_sqr_bb` (X02 채택본) | 71 | **69.0%** (49) | 49.3% | 36.6% | 31.0% (22) | **39** |

- 본문 내내 비는 레지스터는 **둘 다 없다.** 그래서 "고정 레지스터 하나를 게스트에 준다"는 안 된다.
- 그러나 **삽입 지점의 60~69% 에는 빈 것이 1개 이상 있다.** 게스트가 필요한 것은 그것뿐이다.
- free = 0 인 지점(31~40%)에는 **스칼라 불필요 MVE**(`vadd`/`vsub`, 46개 중 16개)를 배치한다.

**호스트 선택**: 표적 크기는 mul(encaps 26.1%) > sqr(22.5%)이지만, 할당 여유는 sqr 이
훨씬 낫다(최장 연속 39 vs 16). **sqr 로 먼저 증명하고 mul 로 확장**한다.

## 3. 설계

### 3.1 게스트 상태의 표현

| 게스트 값 | 원본 레지스터 | 재물질화 방법 | 명령 수 |
|---|---|---|---:|
| `modulus = −3329` | `r12` | `movw rF, #0xF2FF` (S16 스칼라는 하위 16비트만 쓴다 — 원본도 `:lower16:` 으로 넣는다) | 1 |
| root | `r8` | `movw rF, #root_lo16` | 1 |
| root_twisted | `r9` | `movw rF, #twisted_lo16` | 1 |
| 적재 베이스 | `r11` | `movw rF,#:lower16:buf` + `movt rF,#:upper16:buf` (**실험용 — 정적 버퍼**) | 2 |
| 저장 베이스 | `r7` | 위와 같음 | 2 |

> 베이스를 절대주소로 재생성하는 것은 **정적 버퍼를 쓰는 이 실험에 한정**된다.
> 제품 통합에서는 스택 슬롯 2개(`ldr rF,[sp,#k]`, 1명령)로 바꾼다. 비용은 같은 등급이다.

### 3.2 게스트 명령의 변환 (펼침)

`layer67` 본문 46 명령 × 4 iteration 을 펼치면서:

- `vldrw q, [r11, #k]` → `vldrw q, [rF, #(96·iter + k)]`
- `vldrw q, [r11], #96` (포스트인크리먼트) → `vldrw q, [rF, #(96·iter)]` — 증가는 **imm 에 흡수**
- `vstrw q, [r7], #64` / `[r7, #k]` → `vstrw q, [rF, #(64·iter + k)]`
- `vmul/vqrdmulh/vmla q, q, r8|r9|r12` → 같은 명령, 스칼라 피연산자만 `rF`
- `vadd/vsub q,q,q` → 불변

MVE 의 **의미는 하나도 바뀌지 않는다.** 스칼라 레지스터 이름과 주소 형태만 바뀐다.

### 3.3 할당 알고리즘 (`guest_alloc.py`)

```
입력: 호스트 .S (불변), 게스트 본문, iter 수, 베이스 주소·상수
1. 호스트 파싱 → 역방향 라이브니스 → 각 삽입점 i 의 free_i = REGS − live_after[i]
     (REGS = r0..r12. lr·sp 는 제외 — §5)
2. 게스트 펼침 (§3.2) → MVE 열 G[0..183], 각 항목에 need ∈ {none, const_c, base_b}
3. 배치: 균일 목표 위치 t_j = j · (호스트 길이 / 184)
     need = none  → 정확히 t_j
     need ≠ none  → t_j 이후 가장 가까운 free ≥ 1 인 지점 (순서 보존)
4. 레지스터 선택 + 재물질화:
     삽입점 i 에서 free_i 중 하나 rF 를 고른다.
     같은 삽입점에 연속 배치된 게스트 명령들은 **같은 rF 를 재사용**하고,
     직전 재물질화 값과 같으면 **재물질화를 생략**한다 (상수 캐시).
     삽입점이 바뀌면(사이에 호스트 명령이 있으면) 캐시를 무효화한다 — 호스트가 rF 를 썼을 수 있다.
5. 코드 생성: 호스트 명령 사이에 [remat…, MVE] 묶음을 끼워 넣는다.
     묶음 내부에는 호스트 명령이 들어가지 않는다 (remat 과 그 사용 사이의 원자성).
출력: 병합 .S + 리포트(삽입점별 free 수, 재물질화 명령 수, 캐시 적중률)
```

### 3.4 정확성 논거

- **호스트**: 명령열이 바뀌지 않는다. 게스트는 **그 지점에서 죽어 있는 레지스터에만 쓴다.**
  죽어 있다 = 호스트가 다음에 그 레지스터를 읽기 전에 반드시 다시 쓴다. 따라서 호스트가
  관찰하는 값은 불변이다. (플래그: 게스트가 넣는 `movw`/`movt`/MVE 는 플래그를 바꾸지 않는다.)
- **게스트**: MVE 의미 불변(§3.2). 재물질화된 값은 원본과 같은 값이다.
- **둘 다 검증으로 확인한다** — 논거만으로 채택하지 않는다(§7).

### 3.5 비용 추정 (**추정** — 측정 전)

| 항목 | 값 |
|---|---:|
| 재물질화 명령 (캐시 없을 때) | (16 상수 + 14 베이스×~1.5) ≈ 37 / iter → **148** |
| 재물질화 명령 (상수 캐시, 인접 배치 가정) | 약 **60~80** |
| 게스트 MVE | 184 |
| 삽입 스칼라 총량 (재물질화만) | 60~148 명령 × 0.34 (expCE) = **20~50 cyc** |
| 호스트 sqr 단독 | 약 85 cyc (in-context, expBQ) |
| **기대**: `C ≈ A + 0.34·(호스트 71 + 재물질화)` | = 238 + 24~40 + 20~50 = **282~328** vs 순차 238 + 85 = 323 |

**정직하게: 재물질화가 많으면 이득이 사라진다.** 상수 캐시 적중률이 성패를 가른다.
§7 의 gate 는 이것을 묻는다.

## 4. 왜 이 설계가 규칙 9("손 asm 은 재정렬만")와 충돌하지 않는가

호스트 asm 은 **재정렬조차 하지 않는다** — 그대로다. 게스트의 스칼라 레지스터 이름을
바꾸는 것은 expBK 가 `r6` 추가 사용으로 이미 한 종류의 변경이며, 게스트는 커스텀 ABI 가 없다.
**예외 선언이 필요 없다.**

## 5. 위험

1. **free = 0 지점이 31~40%** → 스칼라 필요 MVE 가 free ≥ 1 지점으로 몰린다.
   배치가 불균일해지면 expCE 의 0.34 법칙이 깨질 수 있다(그 법칙은 균일 배치에서 쟀다).
2. `lr` 을 할당 대상에서 **제외**한다. 두 호스트 모두 본문에서 `lr` 을 일반 레지스터로 쓰지만,
   플랫 프레임의 반환은 스택(`pop {pc}`)이라 살아 있지 않다 — 그래도 안전 여유로 뺀다.
3. 절대주소 재물질화는 실험 한정(§3.1).
4. `.text` 증가: 펼친 몸통 4 iter + 재물질화 ≈ 400~450 명령. ITCM 예산 밖(`.text`).
5. 호스트 라이브니스 계산이 틀리면 **조용히 오답**이 난다. §7 의 1,049 벡터 검사가 방어선.
   (mul 은 expBM 에서 같은 검사 절차를 이미 갖췄다. sqr 도 같은 형태로 만든다.)

```
measure-harness/expBB-src/guest_alloc.py
  ├─ host_liveness(host_body)          -> free_i 목록          (resched.parse 재사용)
  ├─ unroll_guest(body, iters, ...)    -> [(mve_text, need)]
  ├─ place(free, guest)                -> [(insert_point, guest_idx)]

```
`resched_mve.py` 와는 별개다(그쪽은 재정렬, 이쪽은 병합). 둘 다 `resched.parse` 를 공유한다.

## 7. 사전등록 (구현 전 고정)

### 7.1 정확성 (전부 필수)

- **호스트**: 병합 커널의 sqr(또는 mul) 출력 = 단독 커널 출력, **경계 7² + 무작위 1,000 벡터,
  limb 단위 mismatch 0** (expBM 절차 그대로).
- **게스트**: 병합 커널의 NTT 출력 = 단독 NTT 출력, **바이트 mismatch 0**.
  **q0–q7 결정적 초기화 포함**(expCD §2 의 교훈).
- 기존 하네스 `harness_fails = 0`.

### 7.2 성능 — `A` = NTT 단독(layer67×4), `B` = 호스트 단독, `C` = 병합

- **CG-1: 은닉률 `(A + B − C) / B ≥ 50%`** — 호스트의 절반 이상이 공짜여야 한다.
  (expCE 법칙이 재물질화 부담을 더해도 살아남는지 묻는다. 법칙대로면 71% 근처.)
- **CG-2: `C < A + B`** — 순차보다 느리면 실패다.
- 리포트 항목: 재물질화 명령 수, 상수 캐시 적중률, 삽입점별 free 분포.

CG-1 통과 → **mul 호스트로 반복**(같은 gate). 둘 다 통과하면 **full X-Wing 통합(구조 문제)** 로.
CG-1 실패·CG-2 통과 → 재물질화 비용이 원인이면 캐시 개선 1회만 허용(사후 임계값 변경 없음).
CG-2 실패 → 이 설계를 종료한다.

## 8. 미측정·한계 (설계 시점)

1. §3.5 는 전부 **추정**이다.
2. 불균일 배치에서 0.34 법칙이 유지되는지 **미측정**(§5-1).
3. 호스트 sqr 의 in-context 단가 85 는 expBQ 의 파생값이다.
4. 이 설계는 **한 NTT 루프(layer67)** 만 다룬다. 다른 루프(`layer45`, 7 레지스터)는
   상수·포인터 구성이 달라 재물질화 표를 따로 세워야 한다.
