# 분석 CF — 스티칭 트랙 결산: **측정할 것은 다 쟀다. 남은 것은 도구 하나다**

> 2026-08-27. 새 보드 측정 없음. expBZ·expCA·expCB·expCC·expCD·expCE 의 종합.

| 7 | 2% 창 기준 **공짜 용량은 0** | expCD (CD-1 FAIL) |

## 2. 남은 유일한 장애물 — **레지스터 할당기**

X25519 커널을 원본 소스에서 세었다.

| 커널 | 명령 | 스칼라 레지스터 | 여유 |
|---|---:|---:|---|
| `apx_real_fe25519_mul` | 120 | **14** | **없음** |
| `apx_real_fe25519_sqr` | 94 | **14** | **없음** |
| `apx_real_fe25519_add` | 24 | **14** | **없음** |
| `apx_real_fe25519_sub` | 25 | **14** | **없음** |
| `fe25519_sqr_bb` (X02 채택본) | 94 | **14** | **없음** |
| `fe25519_mul_sched` (X01 채택본) | 120 | **14** | **없음** |

`intt layer67` 은 **5개**(`r7` 저장포인터 · `r11` 적재포인터 · `r8` `r9` `r12` 스칼라 피연산자)를
쓴다. **합 19 > 14.** 5개가 모자란다.

### 2.1 그런데 스필 비용은 **문제가 아니다**

expCE 가 메모리 비율 0~32% 에서 `k` 가 **평평**함을 보였다(0.274~0.288).
즉 **삽입한 `str`/`ldr` 도 `umaal` 과 똑같이 0.34 cyc** 이다.

```
5개 레지스터를 스필하는 데 드는 추가 명령을 20개로 잡으면
   병합 안에서의 비용 = 20 x 0.34 = 6.8 cyc
   fe25519_mul 한 번(스티칭 41 cyc) 대비 17%
```

**즉 막힌 것은 "스필이 비싸서"가 아니라 "스필을 넣어 재할당해 줄 도구가 없어서"다.**

### 2.2 NTT 쪽을 줄이는 길 — **확인했고, 닫혔다**

`r8` `r9` `r12` 는 MVE 명령의 **스칼라 피연산자**이고 전부 루프 불변 상수다
(원본 소스 확인: `r12 = modulus = -3329`, `r8`·`r9` 는 layer67 전용 root 값).

| 원본 | 사용 | 벡터-벡터 대체 |
|---|---:|---|
| `vmul.S16 q,q,r8` | 4 | `vmul.i16 q,q,qA` — **있다** |
| `vqrdmulh.S16 q,q,r9` | 4 | `vqrdmulh.s16 q,q,qB` — **있다** |
| `vmla.S16 q,q,r12` | 8 | **없다.** `vmul.i16 qt,qn,qC` + `vadd.i16 q,q,qt` 로 풀어야 한다 |

따라서 `vdup` 로 옮기려면 **q 레지스터 4개**(상수 3 + `vmla` 분해용 임시 1)가 더 필요하다.

**layer67 본문의 q 라이브니스를 계산했다** (루프를 2회 펼쳐 정상 상태 구간을 봄):

```
최대 동시 라이브 q = 8 / 8
루프 내내 죽어 있는 q = 없음
q별 라이브 비율: q0 76% q1 76% q2 39% q3 70% q4 74% q5 67% q6 46% q7 74%
```

**여유 0. 필요 4. → `vdup` 경로는 닫혔다.**

(q2 39% · q6 46% 처럼 라이브 비율이 낮은 것이 있지만, **상수는 루프 내내 살아 있어야
하므로** 빈 구간이 있다는 것만으로는 쓸 수 없다.)

### 2.3 그래서 어느 길로 가든 **재할당이 필요하다**

| 길 | 부족분 | 판정 |
|---|---:|---|
| 그대로 병합 | 스칼라 **5개** | 재할당 필요 |
| `vdup` 로 NTT 를 2개까지 줄임 | 스칼라 **2개** + **q 4개** | **q 여유 0 → 닫힘** |

X25519 커널 6종이 모두 14/14 이므로 **어떤 조합이든 X25519 쪽 재할당을 피할 수 없다.**

## 3. 그래서 지금 인용 가능한 것과 아닌 것

| | 상태 |
|---|---|
| 커널 수준 스티칭이 **동작한다** | **실측·인용 가능** |
| 겹침 규칙 표 | **실측·인용 가능** |
| 누출 법칙 0.34 cyc/명령 | **실측·인용 가능** (expCD 로 교차검증) |
| 할인율 71% | **실측·인용 가능** |
| `fe25519_mul` 호출당 64 cyc 절감 | **투영** — 법칙 적용값, 실측 아님 |
| X-Wing 평균 약 2.2% | **투영** — full 미측정 |

## 4. full X-Wing 통합이 왜 아직인가 — 두 겹의 문제

1. **레지스터**(§2). 도구가 필요하다.
2. **구조**. `xwing_enc` 는 `crypto_kem_enc()` 를 부른 뒤 X25519 를 부른다.
   두 스트림을 엮으려면 ML-KEM 내부(`indcpa_enc` → `polyvec_invntt`)와 X25519 래더를
   **같은 함수 안으로** 끌어와야 하고, Lenngren 래더는 255회 단일 루프라 **재진입이 안 된다.**
   X06 comb(86 window)는 window 단위로 쪼갤 수 있어 상대적으로 낫다 — **미시도**.

## 5. 다음에 할 일 (우선순위)

1. ~~`vdup` 경로~~ — **확인 결과 닫혔다**(§2.2). q 여유 0.
2. **스필 삽입 레지스터 할당기**가 유일한 길이다. `resched_mve.py` 에 얹는다.
   목표는 작다: `fe25519_mul` 에서 **5개**를 스택으로 내리는 것.
   expCE 가 스필 명령도 0.34 cyc 임을 보였으므로 **비용은 문제가 아니다.**
3. 구조 문제는 **X06 comb 부터**(86 window, 분할 가능). Lenngren 래더(255회 단일 루프)는
   재진입이 안 되므로 나중이다.

## 6. 미측정 목록 (이 트랙에서 남기는 것)

1. full X-Wing 통합 절감 — **미측정**.
2. `0.34 cyc/명령`의 **원인** — 미규명.
3. `vldrw` × 스칼라 저장, `vstrw` × 스칼라 적재 조합 — 미측정.
4. ~~`vdup` 안~~ — **측정 완료, 닫힘**(§2.2).
5. `intt layer67` 외의 NTT 루프 — 미측정.
6. 스칼라 스트림은 Keccak extract 와 합성 스트림 두 종류뿐 — 실제 X25519 커널로는 미측정.

## 7. 정직 기록

1. **이 문서는 새 측정이 아니다.** 기존 실측의 종합이며, §2 의 레지스터 수만
   이번에 원본 소스에서 새로 세었다.
2. §2.1 의 "스필도 0.34" 는 expCE 의 **메모리 비율 평평함**에서 온 추론이다.
   스필을 실제로 넣어 재보지는 않았다.
3. §3 의 "투영" 두 줄을 절감률로 인용하지 않는다.
