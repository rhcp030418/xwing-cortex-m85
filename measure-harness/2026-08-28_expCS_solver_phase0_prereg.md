# 사전등록 — 실험 CS: 융합 조각 phase 0 을 SLOTHY 로 재스케줄해 in-context 측정

> 작성 2026-08-28, **측정 전**. 출처: `paper/리뷰_v8_상위학회.md` P0-3(강).
> 질문: 종단간 후보 U 는 균등 지퍼 산출물이고 솔버를 쓰지 않았다. 같은 재료를 솔버로 다시 스케줄하면 부호가 뒤집히는가?

## 1. 대상

`fiat_mul_u4_p0` — 실제 U 의 1-job 융합 구간에서 24라운드 × 1회 = 24회 호출되는 조각.
본문 592명령(스칼라 fiat 곱 + Keccak b1 조각 1/4).

- A = **F** `x25519_u_bench_seq4` — 순차(x4 24라운드 + Fiat 96 step). 정본 85,196–85,210 cyc.
- B = **U** `x25519_u_bench_fused4` — 지퍼 4조각. 정본 87,138–87,168 cyc.
- C = **U_s** `x25519_u_bench_fused4s` — p0 만 솔버 재스케줄본 `fiat_mul_u4s_p0`, p1–p3 는 U 와 동일.

세 경로는 같은 ELF·같은 ITCM 배치·같은 입력·같은 상태 전이를 쓴다. **단일 변수는 phase-0 조각의 명령 순서와 레지스터 할당뿐이다.**

## 2. 솔버 파이프라인 (측정 전 확정)

- 입력: 조각 본문을 안전 변환 3칙으로 정규화(`gen_exp_cs.py`) → 606명령.
  ldrd/strd 분해(축약형 `ldrd Rt,[b,#k]` = Rt,Rt+1 포함), 스필 슬롯 고유화(58슬롯·232B), `sp→r13`/`lr→r14`, 음수 즉치 16진화.
- 모델: 상류 SLOTHY `241093fa` + 본 연구 패치 v0.1–v0.5. **v0.5 신규**: 벡터 베이스 개더/스캐터
  (`vldrw.u32 Qd,[Qn,#imm]` / `vstrw.u32 Qd,[Qn,#imm]`) 클래스 2종 — b1 경로에 필요한데 상류에 없었다.
  자원 배정은 상류 `vldrw_gather`(LOAD)와 v0.4 규칙(벡터 스토어가 스칼라 슬롯 차단)을 따르며,
  개더/스캐터의 실제 처리율·지연은 **미측정**이므로 근사다. 판정은 보드가 한다.
- 예약: 상류 기본(flags, r13, r14, HINT) + **r11**(b1 베이스) + **q7**(개더 베이스).
  출력: q0–q7 전부(조각 경계를 넘어 다음 phase 가 이어받을 수 있으므로 보수적).
- 분할 휴리스틱 factor 16, repeat 2, 창당 timeout 300초.

## 3. 측정

슬롯 862..867 = F U U_s U_s U F. REP_N=100 중앙값, 독립 flash/run 2회.
매 반복마다 기존 `bench_expaf_path_reps` 의 정확성 검사를 그대로 쓴다.

## 4. 사전 고정 gate

### 4.1 정확성 (하나라도 실패하면 성능 수치 폐기)
- U_s 의 Keccak 상태 `states[4][25]` 가 순차 참조 `expaf_ref4` 와 **바이트 일치**.
- 같은 반복의 X25519 출력이 `alice_pk` 와 일치, `x25519_u_failures()==0`.
- 전체 하네스 `harness_fails=0`, `KAT ALL PASS`.

### 4.2 판정 (측정 전 고정, 어느 쪽이든 원고에 그대로 싣는다)
- **U_s < U**: 솔버가 지퍼를 이긴다. 개선폭을 4조각 전체로 외삽하지 않고 phase-0 한 조각의 효과로만 보고한다.
  U_s < F 까지 가면 음성 결과의 방향이 바뀌므로 나머지 3조각도 재스케줄해 재측정한다.
- **U_s ≥ U**: 솔버로도 지퍼를 이기지 못한다. 원고의 음성 결과가 "지퍼 탓"이 아님을 실증하는
  훨씬 강한 근거가 되며, 한계 절의 P0-3 문장을 실측으로 바꾼다.
- 어느 경우든 U_s−U 를 F 대비 백분율과 조각 1회당 cycle 로 함께 보고한다(호출 24회/1-job).

### 4.3 상수시간
재스케줄은 명령 순서·레지스터 할당·고정 스택 오프셋만 바꾼다. 비밀 의존 분기·주소 없음.

## 6. 사전등록 보정 (2026-08-28, 솔버 완료 **전**에 측정·기록)

빌드·측정 파이프라인을 먼저 검증하다가 두 가지가 드러나 설계를 보정했다. 둘 다 솔버 출력이
존재하기 전에 측정했으므로 결과를 보고 고른 것이 아니다.

### 6.1 배치 단일변수 위반 정정
`fiat_mul_u4_p0` 는 expAM1b 에서 flash 로 퇴거돼 `.text.fiat_u_stitch` 에 있는데
새 조각을 ITCM 에 두었더니 F 셀조차 86.2k/92.5k 로 갈렸다. 새 조각을 같은 종류의 flash
섹션(`.text.fiat_u_stitch_cs`)으로 옮기자 F 두 셀이 86,239 로 **완전히 일치**했다.

### 6.2 변환 세금 대조군 Ut 추가 (슬롯 8개로 확대)
안전 변환(ldrd/strd 분해 +14명령, 스필 고유화, 프레임 144→240B)은 스케줄과 무관한 비용을
만든다. 그래서 **같은 변환을 거쳤으나 명령 순서는 원본 그대로**인 `fiat_mul_u4t_p0` 를 추가했다.
슬롯 862..869 = F U Ut Us Us Ut U F. 판정의 분모는 U 가 아니라 **Ut** 다:
`Us − Ut` 만이 순수한 스케줄 효과다.

### 6.3 주소 효과 보정값 (identical-content calibration)
`u4s` 를 `u4t` 의 **바이트 동일 사본**으로 두고 잰 결과:

| 셀 | median | 비고 |
|---|---:|---|
| F (862/869) | 86,239 / 86,239 | 완전 일치 |
| U 지퍼 (863/868) | 92,969 / 93,001 | |
| Ut 변환 (864/867) | 94,865 / 94,915 | Ut−U = +1,896/+1,914 (**변환 세금 ≈ 79 cyc/호출**) |
| Us (865/866) | 94,187 / 94,157 | **내용이 Ut 와 같은데 −678/−758** |

두 심볼은 flash 주소가 다르다(`u4t` 0x020201d0, `u4s` 0x020209a0). 내용이 같은데도
**−718 cycle(평균)** 차이가 나므로 이것이 이 비교의 주소·캐시 바닥이다.
따라서 솔버 본문을 넣은 뒤의 순수 스케줄 효과는
```
스케줄 효과 = (Us − Ut) − (−718)
```
이며, |스케줄 효과| < 718 이면 **주소 효과와 구분 불가**로 보고한다.
명령 수와 인코딩이 불변(재정렬 전용)이라 코드 크기·정렬은 그대로다.

원시: `logs/2026-08-28_expCS_placement_calibration.txt`
(ELF `B256D32E…`, readback `6FA7F740…`, `harness_fails=0`, `mismatch=0`).

## 7. run 1 폐기 기록 (2026-08-28) — 정확성 게이트 FAIL

§4.1 대로 성능 수치를 폐기했다. 결과를 보고 사후에 만든 예외가 아니라 사전 고정 게이트의 작동이다.

| | 값 |
|---|---|
| ELF | `E9090FC6…` / readback `325F3CB1…` |
| `harness_fails` / mismatch | **6,400** (Us 셀 2개 × 100회 × 32바이트) |
| KAT | PASS (실패는 Us 경로에 한정) |
| 로그 | `logs/2026-08-28_expCS_run1_FAILED_v05model.txt` |

**원인.** SLOTHY 모델 패치 v0.5 는 벡터 베이스 개더/스캐터
(`vldrw.u32 Qd,[Qn,#imm]` / `vstrw.u32 Qd,[Qn,#imm]`)를 파서에만 추가하고,
arch 의 `is_load_store_instruction` / `is_vector_load` / `is_vector_store` 목록에
넣지 않았다(그 목록은 메서드 본문에 하드코딩돼 있다). 그래서 솔버는 이 명령들을
메모리 접근으로 보지 않고 같은 Keccak 상태 워드에 대한 적재·저장을 자유롭게 재배치했다.
창 36개가 전부 OPTIMAL 이었고 selfcheck 36개도 전부 통과했지만 보드에서는 틀렸다 —
**selfcheck 는 솔버가 아는 데이터 흐름만 검사한다.**

**조치 (v0.6).** 두 클래스에 `make()` 로 `addr`/`pre_index` 를 달고
`is_load_store_instruction`/`is_vector_load`/`is_vector_store` 를 서브클래스에서
재정의했다. 상류 이슈 초안 5번으로 기록했다(`slothy-2stream/upstream_issues.md`).

**부수 발견 (Issue 4).** 그 앞 시도에서는 솔버가 `lsrl r8, r6` 같은 불법 쌍을 만들어
어셈블 자체가 실패했다. Armv8.1-M `LSLL/LSRL` 은 RdaLo 짝수·RdaHi 홀수를 요구하는데
모델이 이를 표현하지 못한다. 회피로 해당 12개 명령이 쓰는 r2–r9 를 재할당 대상에서 뺐다
(재정렬은 그대로 자유). 이 제약은 v0.6 재실행에도 그대로 적용된다.
