# 실험 BL 결과 — M85 **shifted-operand ALU·bfi 발행 규칙** 실측 (expBA 확장)

> 측정 2026-08-26. 보드 EK-RA8M1, DWT CYCCNT, REP_N=100, BATCH=64, 커널당 128 명령, `.balign 16`.
> 독립 flash/run 2회 **비트 단위 동일**.
> 동기: expBK 가 실현율 0.37 로 모델과 어긋났고, 그 원인 후보로 shifted-operand 를 **추정**했다.
> **이 문서가 그 추정을 반증한다.**

---

## 1. 원시 측정 (커널 총 cyc/호출, 128 명령)

| 커널 | 내용 | 총 cyc |
|---|---|---:|
| A `plain_indep` | `eor rD, rN, rM` 독립 4-way | **175.05** |
| B `plain_dep` | `eor rD, rD, rM` 의존 체인 | **244.95** |
| C `shift_indep` | `eor rD, rN, rM, LSR #8` 독립 4-way | **175.05** |
| D `shift_dep` | `eor rD, rD, rM, LSR #8` 의존 체인 | **244.95** |
| E `mix_indep` | shifted 와 평 ALU 교대, 독립 | **175.05** |
| F `andimm_indep` | `and rD, rN, #0x0C0C0C0C` 독립 4-way | **175.05** |
| G `bfi_indep` | `bfi rD, rN, #16, #16` **독립** 4-way | **244.95** |
| H `fbi_chain` | `fromBitInterleaving` 4단 블록 그대로 | **274.95** |

> **null 슬롯은 쓰지 않았다.** null 은 134.95 로 나오는데 그것으로 빼면
> 명령당 0.313 cyc = **IPC 3.2** 라는 불가능한 값이 된다(스칼라 듀얼이슈 상한은 2).
> expBA 가 겪은 것과 같은 문제이며, 여기서도 **커널 간 차분**으로만 해석한다.

## 2. 해석 — 두 미지수를 차분으로 푼다

공통 오버헤드 X(호출·프롤로그·에필로그·루프)와 의존 체인의 유효 지연 L:

```
독립 4-way :  128 x 0.5 + X = 175.05      (듀얼이슈 2/cyc 가정)
의존 체인  :  128 x L   + X = 244.95
```

→ **X = 111.05 cyc**, **L = 1.046 ≈ 1.0 cyc**

X = 111.05 는 null 슬롯의 134.95 와 23.9 cyc 어긋난다 — expBA 의 어긋남(64.86 대 39.20,
차 25.7)과 같은 크기다. **차분법이 정본이다.**

## 3. 확정된 규칙

| # | 규칙 | 근거 |
|---|---|---|
| 1 | **shifted-operand 는 공짜다.** `eor rD,rN,rM,LSR#k` 는 평 `eor` 과 **처리율·지연이 완전히 동일**하다 | A = C (175.05), B = D (244.95), **완전 일치** |
| 2 | shifted 와 평 ALU 는 **서로 페어링된다** | E = A = 175.05 |
| 3 | **`and rD,rN,#imm32` 도 평 ALU 와 같다** (Thumb-2 modified immediate) | F = A |
| 4 | **`bfi` 는 듀얼이슈되지 않는다.** 독립인데도 의존 체인과 같은 속도 = **1/cyc** | G = B = 244.95 |
| 5 | 평 ALU 지연 = **1 cyc**, 처리율 = **2/cyc** | §2 |
| 6 | `fromBitInterleaving` 4단 블록은 **1.28 cyc/명령** — 순수 직렬 사슬(1.046)보다 **22% 느리다** | H = 274.95 |

## 4. expBK 의 §2.1 추정은 **틀렸다**

expBK 결과 문서 §2.1 은 실현율 0.37 의 원인 후보로
"shifted-operand 가 지연 2 이거나 페어링되지 않을 것"이라고 **추정**했다.
**규칙 1·2 가 그것을 반증한다.** shifted-operand 는 완전히 공짜다.

실제 원인은 다른 데 있다:

1. **`bfi` 가 1/cyc**(규칙 4) — lane 프롤로그의 `bfi r4,r5,#16,#16` 이 페어링되지 않는다.
2. **`fromBitInterleaving` 블록 자체가 1.28 cyc/명령**(규칙 6) — 사슬 안에 순수 지연 말고
   무언가 더 있다. `eors`(플래그 설정)나 `and` 의 32비트 인코딩이 후보이나 **미규명**이다.

### 4.1 고친 회계로 본 K32 의 남은 여지

교차 배치 lane 몸통 40 명령의 하한을 규칙 1~6 으로 다시 세우면:

```
ldrd 1 + bfi 1(페어링 불가) + movs/bfc/orr 3개 -> 1.5
사슬 32 명령 / 2 (두 독립 사슬)              -> 16
str 2 (발행 차단)                             -> 2
subs + bne                                    -> 1.5
합계                                        ~= 24 cyc/lane
```

**실측 35.46 cyc/lane 대비 여전히 1.48배 여지가 있다.**
단, 규칙 6(1.28 cyc/명령)을 사슬에 적용하면 하한이 올라가므로 이 24 는 **낙관적 하한**이다.

**K32 는 expBK 의 사전등록 gate 로 이미 종료됐다. 이 문서는 그것을 되살리지 않는다.**
다시 열려면 새 사전등록이 필요하다.

## 5. 도구 반영

`measure-harness/expBB-src/resched.py` 의 지연 모델에 규칙 4를 넣는다
(`bfi` 는 페어링 불가 → `str` 과 같은 취급). 규칙 1·2·3 은 **현재 모델이 이미 맞게
다루고 있었다**(shifted operand 를 평 ALU 로 셌다).

## 6. 미측정·한계

1. **규칙 6 의 원인 미규명** — `eors` 플래그 설정인지, `and` 인코딩인지, 다른 것인지 분리하지 않았다.
2. `bfc`·`ubfx`·`rbit` 등 다른 비트필드 명령은 **미측정**. `bfi` 만 쟀다.
3. `lsl`/`lsr` 독립 명령(shift-only)은 **미측정**.
4. 오버헤드 X = 111.05 는 §2 의 "독립 4-way 는 정확히 2/cyc" 가정에서 나온 **유도값**이다. 그 가정이 틀리면 L 도 흔들린다. 다만 A=C=E=F 가 완전 일치하는 것은 가정과 무관한 사실이다.
5. EK-RA8M1 한 개체, 이 배치 한정.
