# 실험 BJ 결과 — K24 분모 분해, 그리고 **메모리 배치가 6.85배**라는 발견

> 측정 2026-08-26. 보드 EK-RA8M1, DWT CYCCNT, REP_N=100, BATCH=16.
> 분모 측정 실험이다(성능 후보 아님). 선행: expAQ(squeeze 993 cyc/회), expAO(순열 5,504).

---

## 1. 가장 중요한 결과 — Keccak 상태를 어디 두느냐가 **6.85배**다

**같은 `KeccakF1600_StatePermute`, 같은 빌드, 상태 버퍼 위치만 다르다.**

| 상태 위치 | 순열 1회 | 비 |
|---|---:|---:|
| `.bss` (SRAM) | **37,705.94** | 6.85× |
| DTCM 스택 | **5,505.81** | 1.00× |

DTCM 값 5,505.81 은 expAO 의 하네스 실측 **5,504** 와 일치한다 — 실제 X-Wing 경로는
`xof_state` 를 스택 지역변수로 두므로 **이미 DTCM 이다.** 따라서 이 발견은 X-Wing 을
더 빠르게 만드는 후보가 아니라 **측정 규율**이다.

### 1.1 저장은 싸고 적재가 비싸다

| 조각 | `.bss` | DTCM | 비 | 성격 |
|---|---:|---:|---:|---|
| 200 B 영점화 (워드 store) | 43.09 | — | — | store만 |
| 200 B 복사 (워드 ldrd/strd) | 442.98 | **77.75** | 5.70× | load+store |
| 200 B 복사 (newlib memcpy) | 2,522.75 | **418.81** | 6.02× | load+store |

store 는 두 곳에서 모두 싸고(버퍼링), **load 가 SRAM 에서 약 6배 비싸다.**
순열이 6.85배인 것도 몸통이 `ldr` 437 / `str` 225 (expBE §2)로 load 우세이기 때문이다.

> **규칙 추가**: 마이크로벤치의 버퍼는 **대상 코드가 실제로 쓰는 메모리와 같은 영역**에
> 두어야 한다. `.bss` 에 둔 probe 로 잰 cyc/byte 를 DTCM 경로에 외삽하면 최대 6배 틀린다.

### 1.2 이 발견이 expBH §2.1 의 "원인 미규명"을 해결한다

expBH 는 keygen 만 예측의 0.48 배였고 원인을 미규명으로 남겼다. **DTCM 수치로 다시
계산하면 맞는다.**

`memcpy` 절감 = 2.09 − 0.39 = **1.71 cyc/byte** (`.bss` 기준 10.40 이 아니라).
`memset` 절감은 세 연산 실측에서 역산하면 2.53 / 2.61 / 2.54 = **약 2.55 cyc/byte**로 일치.

| 연산 | 재예측 | expBH 실측 | 비 |
|---|---:|---:|---:|
| keygen (1,184 B memcpy + 3,400 B memset) | 2,025 + 8,670 = **10,695** | 10,634 | **0.99** |
| encaps (3,800 B memset) | 9,690 | 9,922 | 1.02 |
| decaps (3,800 B memset) | 9,690 | 9,671 | 1.00 |

**세 연산 모두 1% 안에서 맞는다.** expBH §2.1 의 불일치는 `.bss` probe 탓이었다.
**expBH 의 판정(채택)은 full X-Wing A/B 로 한 것이므로 영향받지 않는다.**

## 2. K24 분모 — squeeze 배관의 93.2%는 비트-인터리브 해제다

DTCM 상태 기준(실제 경로와 같은 배치):

| 조각 | cyc/호출 |
|---|---:|
| `KeccakF1600_StatePermute` | 5,505.81 |
| `shake128_squeezeblocks`(1 block) | 6,455.81 |
| **배관 = squeeze − 순열** | **950.00** |
| 그중 `KeccakF1600_StateExtractBytes(0,168)` | **885.81 (93.2%)** |
| 호출·루프 기타 | 64.19 (6.8%) |

expAQ 의 993 cyc/회는 rename+wrapper 로 잰 값이며, 여기 950 이 wrapper 없는 값이다
(차 43 cyc ≈ wrapper 비용, expBI §3 과 같은 크기).

### 2.1 K24(squeeze→CBD 융합)의 상한은 작다

K24 는 **168 B 버퍼 왕복을 없애는** 것이다. 그런데 배관의 93.2%는 버퍼가 아니라
`fromBitInterleaving` **연산 자체**이며, 융합해도 그 계산은 남는다.

```
K24 상한 ≈ 호출·루프 기타 64.19 + (168 B store/load 절감)
         ≈ 100 cyc/회 미만  =  배관의 약 10%
28회/연산 × 100 = 2.8 kcyc  =  keygen 0.45% / encaps 0.28%
```

> **판정 보류**: 위는 **추정**이다. 그러나 방향은 분명하다 — **K24 는 표적을 잘못 잡았다.**
> 진짜 표적은 버퍼가 아니라 `KeccakF1600_StateExtractBytes` 자체다.

## 3. 새 후보 K32 — `StateExtractBytes` 재스케줄

| | 값 |
|---|---:|
| 실측 | **885.81 cyc / 168 B** = 42.18 cyc/lane (21 lane) |
| 몸통 명령 수 | **41** (`ldrd` 1 + `fromBitInterleaving` 36 + `str` 2 + `subs` + `bne`) |
| expBA 발행 모델 하한 | store 2 × 0.5 = 1.0 + (39 − 2)/2 ≈ **20.5 cyc/lane** |
| **현재 IPC** | **0.97** |
| **여지** | **약 2.06배 (51%)** |

K19(scalar 순열)는 IPC 1.66 으로 여지 4.6% 뿐이라 종료됐다. **`StateExtractBytes` 는
IPC 0.97 로 정반대다.**

원인 추정: `fromBitInterleaving` 은 `eor→and→eors→eor` 4단 직렬 사슬을 8번 반복하는데,
**x0 에 대한 4블록을 먼저 다 하고 x1 에 대한 4블록을 한다.** 두 반쪽은 **서로 독립**이므로
교차 배치하면 지연을 서로 메울 수 있다. expBB 의 재정렬 전용 스케줄러가 정확히 이 일을 한다.

**분모**: 885.81 × 28회/연산 = **24.8 kcyc/연산**
= keygen **3.98%** / encaps **2.51%** / decaps **3.13%**.

같은 논리가 `KeccakF1600_StateXORBytes`(`toBitInterleaving`)에도 걸린다 — **미측정**.

## 4. 미측정·한계

1. §2.1 의 K24 상한 "100 cyc/회 미만"은 **추정**이다. 실측하지 않았다.
2. §3 의 여지 2.06배는 **정적 발행 모델**이며 latency·분기를 넣지 않았다(expBE 와 같은 한계).
3. `StateXORBytes` 의 DTCM 기준 단가 **미측정**. `.bss` 기준 34 B = 452.78 뿐이다.
4. DTCM `memset` 단가를 직접 재지 않고 §1.2 에서 **역산**했다.
5. `.bss` load 가 6배 비싼 이유(D-cache 비활성/영역 속성)는 **확인하지 않았다.** 측정된 것은 비용뿐이다.
6. EK-RA8M1 한 개체, 이 배치 한정.

## 6. 정직 기록

1. **첫 판정이 틀렸다.** 진단 슬롯의 상태를 `.bss` 에 두어 순열을 37,705 로 쟀고,
   expAO 의 5,504 와 6.85배 어긋났다. 배치 A/B 로 원인을 확정한 뒤 DTCM 기준으로 다시 쟀다.
   **틀린 1,240.94(.bss) 대신 950.00(DTCM)이 정본이다.**
2. 그 실수가 **expBG §2 의 cyc/byte 표 전체를 `.bss` 기준값으로 만들었다.** expBG 문서에
   정정 주석을 단다. **expBG/expBH 의 gate 판정은 full X-Wing A/B 였으므로 유효하다.**
3. §2.1 은 K24 의 표적이 틀렸다는 **추정**이며, 이 문서는 K24 를 종료시키지 않는다.
   종료·전환은 사전등록된 실험으로 판정한다.
