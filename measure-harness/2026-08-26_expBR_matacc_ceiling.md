# 분석 BR — K14/K15(matacc) 발행 여지: **상한 약 2.1%, 종료하지 않는다 (도구 부재)**

> 2026-08-26. **정적 회계**다. expBE §3-3 이 "`matacc_asm_*` 의 여지는 미산정"으로
> 남긴 것을 채운다. 입력: ELF 역어셈블, `matacc.i` 루프 구조, expAP/AQ 실측.

---

> **2026-08-26 정정 (expBX)**: 이 문서의 "MVE 28~32"는 **틀렸다.** 매크로 전개 리스팅을
> 확인한 결과 그것들은 전부 `vmov s18, bufptr` 형태의 **core↔FP 스크래치 이동**이며
> MVE 벡터 산술은 하나도 없다. `vmov` 는 1/cyc 이지만 스칼라와 100% 페어링한다(expBX 실측).
> 그 값으로 다시 세면 하한 70.0, **여유 17.6%**(32.4% 아님)다.
> 또한 루프는 rejection 분기 때문에 **9개 기본블록**으로 조각나 있어 재정렬 회수가 급감한다.
> **최종 판정은 expBX §4 — K14/K15 재정렬 접근 종료.**

## 1. 루프 구조 (ELF + 소스 확인)

여섯 커널 모두 `cmp ctr, #256/4` / `blt.w 1b` 형태의 단일 외부 루프다 → **반복 64회**.

| 커널 | 몸통 명령 | 곱셈 | store | MVE | 스칼라 |
|---|---:|---:|---:|---:|---:|
| `matacc_asm_cache_16_32` | 113 | 16 | 14 | 28 | 85 |
| `matacc_asm_cache_32_32` | 121 | 20 | 14 | 28 | 93 |
| `matacc_asm_cache_32_16` | 141 | 36 | 10 | 32 | 109 |
| `matacc_asm_opt_16_32` | 93 | 0 | 10 | 28 | 65 |
| `matacc_asm_opt_32_32` | 101 | 8 | 10 | 28 | 73 |
| `matacc_asm_opt_32_16` | 121 | 24 | 6 | 32 | 89 |

## 2. 반복당 실측 (파생)

| | cyc | 근거 |
|---|---:|---|

| sub-call 하나 | 약 **5,450** | |
| 반복 64회로 나눈 **반복당** | 약 **85 cyc** | |

## 3. 발행 하한 (expBA + expBL 규칙, 스칼라만)

`matacc_asm_cache_16_32` 기준:

```
하한(스칼라) = 곱셈 16 + store 14 + (85 - 16 - 14)/2
             = 16 + 14 + 27.5  =  57.5 cyc
```

MVE 28 명령은 이 회계 밖이다. 두 극단:

| 가정 | 하한 |
|---|---:|
| MVE 가 스칼라와 **완전히 겹친다** | **57.5** |
| MVE 가 **전혀 안 겹친다** (2-beat 가정) | 57.5 + 56 = 113.5 |

**실측 반복당 85 는 113.5 보다 작다 → MVE 는 상당 부분 스칼라와 겹쳐 발행된다**
(slothy-2stream README 의 스칼라×MVE 페어링 관측과 일치).

```
여유 = (85 - 57.5) / 85 = 32.4%
```

## 4. 분모와 상한

matacc 에서 XOF 배관을 뺀 몫(= 이 커널들)은 연산당 약 **50.6 kcyc**(expBP §7).

```
상한 = 50.6 k x 32.4%  =  16.4 kcyc / 연산
  keygen  16.4k / 621,106 = 2.64%
  encaps  16.4k / 977,896 = 1.68%
  decaps  16.4k / 785,540 = 2.09%
  세 연산 평균            = 2.14%
```

**expBP §0 기준(1.0%)을 넘는다 → 종료하지 않는다.**

## 5. 그러나 지금 실행할 수단이 없다 — 정직하게 적는다

1. **재정렬 도구(`resched.py`)는 MVE 를 모델링하지 않는다.** 이 커널은 명령의 25~30% 가
   MVE 이고, 스칼라×MVE 페어링이 결과를 좌우한다. 도구를 그대로 쓰면 baseline 재현에
   실패할 것이 거의 확실하고, 규칙 5 에 따라 보드에 올릴 수 없다.
2. **SLOTHY 는 이 프로젝트에서 사용 불가로 이미 판정됐다**
   (`slothy-2stream/README` §135: 레지스터 포화 손 asm 은 스필 삽입 없이 스케줄 불가).
   `matacc_asm_*` 는 레지스터를 전부 쓰는 매크로 전개 커널이다.
3. 커널이 **매크로 6종 × 조건 분기(rejection)** 구조라 평탄한 단일 블록이 아니다.
   expBD 가 `fe25519_mul` 에서 겪은 조각화 문제가 여기서는 훨씬 심하다.

**→ K14/K15 는 "상한은 충분하나 수단이 없다"로 남긴다.**
수단은 **MVE 를 모델링하는 스케줄러**이며, 그것을 만드는 것은 별도 과제다(T 계열).

## 6. 미측정·한계

1. §2 의 "sub-call 하나 5,450"은 **차분에서 나온 파생값**이다. 직접 계측하지 않았다.
2. 반복당 85 는 rejection 재시도와 squeeze 콜백을 뺀 뒤의 **평균**이다. rejection 은
   공개 seed 에 따라 변동하므로 반복마다 다르다.
3. MVE 명령의 실제 발행 비용 **미측정**. §3 의 두 극단은 문헌 가정이다.
4. expAP 버킷은 계측 wrapper 빌드의 값이므로 비중·상한에만 썼다(규칙 8).
5. EK-RA8M1 한 개체, 이 배치 한정.
