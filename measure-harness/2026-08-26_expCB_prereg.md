# 사전등록 — 실험 CB: 스티칭 재재단(①)과 **메모리 포트 경합**(②)

> 작성 2026-08-26, **측정 전**. expCA-1 의 두 후속.
> expCA-1 은 **정확성 완전 통과**했고 성능은 부분 성공(은닉률 63.1%)이었다.
> 그 FAIL 은 메커니즘이 아니라 **내가 lane 수를 잘못 재단한 것**이다(expCA §3).

---

## 1. 배경 (expCA 실측)

| | 값 |
|---|---:|
| A layer67 본문 ×4 (184 MVE) | **236.69** → **1.29 cyc/MVE 명령** |
| B Keccak lane ×8 (312 스칼라) | **308.69** → **38.59 cyc/lane** |
| C 병합 | **350.62** |
| 이론 최선 `max(A,B)` | 308.69 |
| 실측 / 이론 | **88%** |

`expBZ` 가 잰 **MVE 2.000 cyc/명령은 `vmul.i16 q,q,q` 한 종류**의 값이고,
NTT 의 혼합 명령열은 **1.29** 다. 그래서 B > A 가 되어 gate 기준이 뒤집혔다.

## 2. ① 재재단 — lane 수를 A 아래로

`B < A` 가 되도록 **6 lane**(6 × 38.59 = 231.5 < 236.69)으로 줄인다.
그러면 이론 최선이 `A = 236.69` 가 되어 "스칼라가 MVE 밑에 완전히 숨는가"를 직접 묻는다.

**바뀌는 것은 lane 수뿐**이다. 커널 생성기·병합 규칙·레지스터 배정은 그대로다.

### 2.1 사전 고정 kill gate

은닉률 정의: `hide = (A + B − C) / B`.

- **CB-1a: 은닉률 ≥ 80%** (= `C ≤ A + 0.20·B`)
- **CB-1b: 은닉률 ≥ 60%** (= `C ≤ A + 0.40·B`)

**정확성 (필수)**: C 의 NTT 출력 = A, C 의 Keccak 출력 = B, 둘 다 mismatch 0.

- CB-1a 통과 → **CA-2(확대)로 간다.**
- CB-1b 만 통과 → 부분 성공. §3 의 결과를 보고 다음을 정한다.
- **CB-1b 도 실패 → W03/W04/W05 를 종료한다.**

> expCA 의 은닉률 63.1% 는 B > A 상황의 값이다. 같은 정의로 잰다.

## 3. ② 메모리 포트 경합 — expCA 의 41.93 cyc 을 설명하는가

expBZ 는 **메모리를 건드리지 않는 `vmul`** 로만 100% 겹침을 확인했다.
expCA 의 병합 커널은 MVE 쪽이 `vldrw`/`vstrw`, 스칼라 쪽이 `ldrd`/`str` 을 쓴다.
**둘이 같은 메모리 포트를 다투는지는 미측정**이다.

커널 6종, 각 128 명령, **버퍼는 전부 DTCM**(expBJ 규율):

| | 내용 |
|---|---|
| G `vldrw_only` | 독립 `vldrw.u32 q0-q3, [rN, #k]` ×128 |
| H `ldr_only` | 독립 `ldr r2-r5, [rN, #k]` ×128 |
| **I `mix_ld`** | `vldrw` 64 + `ldr` 64 교대 |
| J `vstr_only` | `vstrw.u32 q0-q3, [rN, #k]` ×128 |
| K `str_only` | `str r2-r5, [rN, #k]` ×128 |
| **L `mix_st`** | `vstrw` 64 + `str` 64 교대 |

### 3.1 판정 (gate 아님 — 메커니즘 측정)

expBA·expBZ 와 같은 **커널 간 차분**으로 해석한다.

```
I 작업량 = max(G/2, H/2)   ->  적재는 겹친다
I 작업량 = G/2 + H/2       ->  적재는 **겹치지 않는다** (포트 경합)
```

`str` 은 스칼라끼리도 발행을 차단하므로(expBA) L 은 경합이 예상되나 **미측정**이다.

이 결과는 **expCA §4 의 41.93 cyc 후보 3번을 확인하거나 기각**한다.

## 4. 위험

1. ①의 6 lane 은 `B < A` 를 만들지만 여유가 5.2 cyc 뿐이다. 배치 교란이 이보다 크면
   판정이 흔들린다 → 독립 2회·ABBA 로 통제한다.
2. ②의 store 커널이 DTCM 버퍼를 덮어쓴다. **정확성 검사 뒤에 돌린다.**
3. ITCM 예산이 이미 빡빡하다(expCA 에서 커널 5종을 `.text` 로 내렸다).
   ②의 커널은 **처음부터 `.text`** 에 둔다 — 메모리 접근 실험이라 명령 인출 위치의
   영향은 상대적으로 작다고 **가정**한다. 이 가정은 결과에 표기한다.

## 5. 바꾸지 않는 것

병합 규칙, 레지스터 배정, invNTT·Keccak 커널 내용, 현행 채택본.
