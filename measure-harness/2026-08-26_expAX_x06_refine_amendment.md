# 사전등록 보정 — 실험 AX (X06 잔여 개선)

> 작성 2026-08-26, **측정 전**. AV(`2026-08-26_expAV_x06_native_prereg.md`)의 후속이며
> 알고리즘·표·comb 파라미터는 그대로다. AV 결과 §7의 잔여 두 항목만 친다.

---

## 1. 무엇을 바꾸나 — 두 가지, 둘 다 field 연산 수를 줄인다

### 1.1 조건부 negate 를 **없앤다** (z3/t3 swap 으로 대체)

AV는 digit 이 음수일 때 `xy2d` 를 `fe25519_sub_lenn(neg, 0, xy2d)` 로 부호 반전하고
8-word cmov 로 골랐다(윈도당 1회 = 86회).

madd 안에서 `c = xy2d · T`, `z3 = d + c`, `t3 = d − c` 이므로

```
c' = −c  ⟹  z3' = d − c = t3,   t3' = d + c = z3
```

즉 **c 를 부호 반전하는 것과 z3/t3 를 맞바꾸는 것이 정확히 같다.** 최종 4 곱은

```
X = x3·t3,  Y = y3·z3,  Z = z3·t3,  T = x3·y3
```

이고 `Z` 는 대칭이며 `T` 는 무관하므로, **X 와 Y 가 쓰는 포인터만 상수시간으로 바꾸면
된다.** field 연산이 하나도 늘지 않는다.

제거되는 것: `fe25519_sub_lenn` 86회(래퍼 포함 ~71 cyc) + 8-word cmov 86회(~30 cyc)
≈ **8,700 cyc**.

### 1.2 inversion 의 squaring 사슬을 native 로 (`fe25519_sqr_chain`)

`fe25519_sqr` 는 **입출력이 모두 r0–r7 레지스터**다. AV는 이를 AAPCS 래퍼로 254회 불러
매번 8 word 를 저장하고 다시 읽었다. 값을 레지스터에 둔 채 n 회 반복하는 asm 루프를
쓰면 그 왕복이 통째로 사라진다.

```
void fe25519_sqr_chain(uint32_t r[8], const uint32_t a[8], uint32_t n);
```

제거 기대치: 254 × (store 8 + load 8 + 래퍼 glue ~20) ≈ **9,000 cyc**.
inversion 의 mul 11회는 그대로 래퍼를 쓴다(소액).

## 2. 바꾸지 않는 것

표, comb 파라미터(w=3, 86 윈도), digit recode, 표 조회 커널, 적용 지점(keygen `pkX`,
encaps `ctX`), field 산술 자체, RFC 7748 입출력 정의.

## 3. 목표 (투영, 실측 아님)

| | AV 실측 | AX 목표 |
|---|---:|---:|
| scalarmult | 261,647 | ~243,000 |
| 현행 대비 | +26.80% | ~+32% |

## 4. 사전 고정 gate

- **성능**: AV의 261,647 대비 **회귀하면 채택하지 않는다**(개선 폭 하한은 두지 않는다 —
  이미 AV가 채택 가능하므로 이번은 순수 추가 개선이다).
- **정확성**: AV/AT-3과 동일하게 전부 필수 —
  RFC 7748 KAT 2종, clamp 경계 4종 + 무작위 64 seed 차분 mismatch 0,
  full X-Wing 8-seed 바이트 동일 + 암묵적 거부 동일, 기존 하네스 mismatch 0.
- **상수시간**: all-zero 대 all-ones 분포가 겹쳐야 한다(AV §5의 기준을 그대로 계승하되,
  판정 문구를 median 동일이 아니라 **분포 겹침**으로 쓴다).
- **자원**: `.text` 증가 보고. 표 크기는 불변이어야 한다.

## 5. 위험

- z3/t3 swap 이 대수적으로 맞는지는 §1.1의 유도가 전부다. **틀리면 KAT 이 즉시 깨진다** —
  1,000 seed 호스트 차분이 아니라 보드 KAT + 68 seed 차분이 1차 방어선이다.
- `fe25519_sqr_chain` 은 `fe25519_sqr` 가 r0–r7 을 그대로 물려받는다는 계약에 의존한다.
  이 계약은 `fe25519_sqr_many` 가 이미 같은 방식으로 쓰고 있으므로 새 가정이 아니다.
- `fe25519_sqr` 는 r8–r12 를 clobber 하므로 루프 카운터와 목적지 포인터를 **스택에**
  둔다(레지스터에 두면 AV의 LOCKUP 버그와 같은 실수가 된다).
