# 분석 BQ — X03(독립 mul/sqr 쌍 융합) 상한 재계산: **종료**

> 2026-08-26. **정적 회계**다. 입력은 expBA/expBL 의 실측 발행 규칙, ELF 명령 수,
> expAR/AS 의 in-context 단가, expBB/BM 의 재스케줄 실측.
> **expBP §4 의 상한(27.7~35.4%)을 이 문서가 정정한다.**

---

## 1. expBP §4 는 틀렸다

expBP §4 는 이렇게 셌다:

```
mul 2개 따로 101 x 2 = 202   vs   융합 하한 73 x 2 = 146   -> 27.7%
```

**곱셈 수만 하한으로 놓고 store 와 나머지 명령을 뺐다.** expBA·expBL 의 실제 회계는

```
하한 = 곱셈 수 + store 워드 + bfi 수 + (나머지 명령 수) / 2
```

이며(expBE §1), store 는 발행을 차단하고 나머지도 2/cyc 이 한계다.

## 2. 제대로 센 하한 — 두 커널 모두 **이미 하한 근처**다

| | 명령 | 곱셈 | store 워드 | 나머지 | **하한** | in-context 실측 | 여유 |
|---|---:|---:|---:|---:|---:|---:|---:|
| `fe25519_sqr` (X02 채택본) | 94 | 53 | 14 | 27 | **80.5** | 약 **84.7** | **5.0%** |
| `fe25519_mul` (X01 채택본) | 120 | 73 | 12 | 35 | **102.5** | 약 **105~108** | **2.4~5.1%** |

in-context 실측 산출:
- sqr: expAR 이 X02 이전 sqr 을 **100.0** 으로 쟀고, expBC 가 full 에서 호출당 **15.1~15.6**
  회수를 실측했다 → 약 **84.7**.
- mul: expAR 이 X01 이전 mul 을 **115.005** 로 쟀고, expBN 이 10 cyc/호출 중 70% 회수를
  실측했다 → 약 **108** (micro 그대로면 105).

## 3. 융합의 전제가 실측으로 무너진다

X03(mul2/sqr2)의 전제는 **"두 독립 스트림을 교차하면 의존 스톨이 메워진다"** 이다.
expBA 가 그 전제를 직접 쟀다:

| expBA 커널 | 결과 |
|---|---|
| A `umaal` **의존** 체인 | **1.000 cyc/명령** |
| B `umaal` **독립** 4-way | **1.000 cyc/명령** |

**의존이든 독립이든 같다.** `umaal` 은 **처리율 한계**(곱셈기 1/cyc)이지 의존성 한계가
아니다. 즉 **곱셈 쪽에는 메울 스톨이 애초에 없다.**

그리고 §2 가 보이듯 비-곱셈 쪽 여유도 2.4~5.0% 뿐이다.

## 4. 융합이 실제로 줄일 수 있는 것 — 호출 오버헤드뿐

두 호출을 하나로 합치면 다음이 한 번으로 준다:

| 항목 | cyc | 근거 |
|---|---:|---|
| `bl` + 복귀 + 인자 `ldr` 2개 | 약 **4** | expAS §3.1 (측정 창 구성) |

곱셈 수·store 워드·나머지 명령 수는 **하나도 줄지 않는다.**
오히려 두 상태를 동시에 살리려면 레지스터가 모자라 **스택 왕복이 늘고, `str` 은 발행을
차단한다**(expBA).

```
sqr 쌍 :  84.7 x 2 = 169.4   ->  융합 상한 165.4   =  2.4%
mul 쌍 : 108.0 x 2 = 216.0   ->  융합 상한 212.0   =  1.9%
```

encaps 에서 mul+sqr 은 48.6%(expAN)이므로

```
encaps 상한 = 48.6% x 약 2.1%  =  1.02%
세 연산 평균 상한             =  약 0.8%
```

**그마저도 추가 스필 store 를 0 으로 놓은 값이다.**

## 5. 판정

**expBP §0 기준(세 연산 평균 상한 1.0%) 미달 → X03(X05 포함) 종료.**

근거를 한 줄로: **`umaal` 이 의존 상태에서도 이미 1.000 cyc 로 돌기 때문에
(expBA), 독립 스트림을 교차해 얻을 것이 없다.**

## 6. 한계 — 이 판정이 기대는 모델의 오차

이 회계의 하한은 expBA/expBL 의 발행 규칙에서 나온 것이고, 그 회계는 과거에

| | 모델 | 실측 | 오차 |
|---|---:|---:|---:|
| `fe25519_sqr` 블록 (expBB) | 85 | 약 96 | −11% |
| `fe25519_mul` 평탄화 블록 (expBM) | 145 | 약 105 | +38% |
| `fromBitInterleaving` lane (expBK) | 26 | 35.5 | −27% |

정도의 오차를 보였다. §2 의 "여유 2.4~5.0%"는 **그 오차보다 작다.**

**그러나 §3 의 판정은 모델이 아니라 실측(expBA A=B=1.000)에 기댄다.**
융합의 전제 자체가 실측으로 부정되므로, 모델 오차와 무관하게 결론은 선다.
§4 의 수치(2.4%, 1.9%)만 모델 성격이며 **절감률로 인용하지 않는다.**

## 7. 미측정

1. **융합 커널을 실제로 만들어 재지 않았다.** 이 문서는 정적 판정이다.
2. 스필 store 증가량 **미측정**(0 으로 놓은 낙관적 상한).
3. `fe25519_add`/`sub` 쌍 융합(같은 피연산자 `ldm` 두 번 → 한 번)은 성격이 다르다.
   add+sub 는 곱셈 8개 · load 16 워드로 **load 우세**이며, 융합하면 load 워드가
   16 → 16(공유)로 반이 준다. **이것은 §3 의 논거가 적용되지 않는다 — 별도 판단이 필요하다.**
   → §8 로 넘긴다.

## 8. `fe25519_addsub` 융합도 **종료** — 공유 쌍이 반복당 2개뿐이다

래더 본문(`x25519-cortex-m4-gcc.s` 660~790)의 add/sub 호출 7개를 피연산자로 분류했다.
expAS 의 실측 호출 수(add 255×3, sub 255×4)와 정확히 일치한다.

| 줄 | 호출 | 피연산자 | 결과 처리 | 공유 쌍? |
|---|---|---|---|---|
| 674 | add | (sp, sp+32) | `push {r0-r7}` | — |
| 684 | sub | (sp+64, sp+96) | `push {r0-r7}` | — |
| 700 | sub | (sp+64, sp) | `stm` | — |
| 746 | add | **(sp+192, sp+224)** | `stm sp` | **쌍 1** |
| 757 | sub | **(sp+192, sp+224)** | `stm sp` | **쌍 1** |
| 767 | add | **(sp, sp+32)** | 바로 `sqr` 로 | **쌍 2** |
| 776 | sub | **(sp, sp+32)** | 바로 `sqr` 로 | **쌍 2** |

두 쌍 사이에서 피연산자 버퍼가 덮어써지지 않는 것도 확인했다(746~757 사이에는
sp+32 와 sp 만, 767~776 사이에는 sp+192 만 갱신된다).

### 8.1 쌍당 절감 상한

| 항목 | cyc | 비고 |
|---|---:|---|
| `ldm` 32 워드 → 16 워드 공유 | **+8** | 2/cyc |
| `bl` + 복귀 1회 절약 | **+4** | expAS 측정 창 |
| 두 `r11` 캐리 사슬 교차 | **+4** | **추정**, 두 사슬은 독립 |
| **쌍 2 의 추가 비용** — 결과 하나를 레지스터로 못 돌려주고 저장·재적재 | **−12** | store 8워드 발행 차단 + load 8워드 |
| 쌍 1 순절감 | **약 +16** | 두 결과 모두 어차피 `stm` 된다 |
| 쌍 2 순절감 | **약 +4** | |

```
scalarmult 당 = 255 x (16 + 4) = 5,100 cyc
encaps(래더 1회, ctX 는 X06 comb) = 5,100 / 977,896 = 0.52%
decaps(래더 1회)                  = 5,100 / 785,540 = 0.65%
keygen(래더 없음)                 = 0%
세 연산 평균 상한                 = 0.39%
```

**expBP §0 기준(1.0%) 미달 → `fe25519_addsub` 융합 종료. X03/X05 계열 전체가 닫힌다.**

### 8.2 왜 상한이 이렇게 작은가

- add/sub 호출 7개 중 **피연산자를 공유하는 것은 4개(2쌍)뿐**이다. 나머지 3개는 융합 대상이 아니다.
- 쌍 2 는 결과가 곧바로 `sqr` 로 들어가 **레지스터로 흐른다.** 융합하면 그 흐름이 끊겨
  저장·재적재 비용이 생기고 절감의 대부분을 먹는다.
- 융합이 줄이는 것은 **load 워드와 호출 오버헤드**이며, 이 커널의 지배항인
  `umaal` 8개와 캐리 사슬은 그대로 남는다.

### 8.3 미측정

1. §8.1 의 "캐리 사슬 교차 +4"는 **추정**이다.
2. 융합 커널을 실제로 만들어 재지 않았다.
3. X06 comb 경로(`ge_madd_native`)의 add/sub 호출은 이 회계에 넣지 않았다 —
   **미측정**이며, 넣으면 상한이 다소 올라갈 수 있다. 다만 comb 는 keygen·ctX 전용이라
   decaps 에는 적용 지점이 없다.
