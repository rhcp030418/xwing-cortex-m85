# 사전등록 — 실험 CE: **누출률 법칙** `k(메모리 비율)`

> 작성 2026-08-27, **측정 전**.
> expCD 가 곡선을 냈다: 병합 시간 `C ≈ A + k·B`, `k = 0.15~0.40`, 은닉률 60~85%.
> 그 `k` 가 **스칼라 스트림의 메모리 비율**에 어떻게 달렸는지는 미측정이다.

---

## 1. 왜 이것을 재는가

expCC 실측: **MVE 저장은 스칼라를 통째로 막고, MVE 적재는 스칼라 적재만 막는다.**
따라서 `k` 는 스칼라 쪽 메모리 비율이 오를수록 커질 것이다 — **추정이며 미측정**이다.

`k(r)` 을 알면 **어떤 커널이든 스티칭 이득을 예측할 수 있다**:

| 커널 | 메모리 비율 `r` |
|---|---:|
| Keccak `extract` lane (expCA~CD 에서 쓴 것) | 3 / 39 = **7.7%** |
| `fe25519_mul_sched` | 약 32 / 120 = **27%** |
| `KeccakF1600_StatePermute` | 662 / 1526 = **43%** |

점 하나를 더 찍는 대신 **곡선 `k(r)` 을 낸다.**

## 2. 방법

MVE 쪽 고정: `intt layer67` 본문 ×4 (`A`, 184 MVE 명령, q0–q7 결정적 초기화 포함).

스칼라 쪽: **길이 156 명령 고정**, 메모리 비율만 바꾼다.

| 판 | 메모리 명령 수 | `r` |
|---|---:|---:|
| r00 | 0 | 0% |
| r08 | 12 | 7.7% |
| r16 | 25 | 16.0% |
| r24 | 37 | 23.7% |
| r32 | 50 | 32.1% |

- 메모리 명령은 `ldr`/`str` 을 반반 섞는다(expCC: 둘의 성질이 다르다).
- 나머지는 `umaal`(스칼라 곱셈, 1.000 cyc) 로 채운다.
- 레지스터 **6개**(`r0`–`r5`)만 쓴다. NTT 5개와 합쳐 11 ≤ 14 → **스필 없음**.
- 버퍼는 **DTCM**(expBJ 규율).

각 판에 대해 `B(r)`(스칼라만)과 `C(r)`(병합)을 재고
```
k(r) = (C(r) − A) / B(r)
```
를 낸다. 병합 규칙은 expCC §1.1 실측 표를 그대로 쓴다.

## 3. 사전 고정 판정

**정확성 (필수)**: 모든 판에서 병합본의 NTT 출력 = `A` 의 출력, mismatch 0.
(스칼라 쪽은 산술 결과를 비교하지 않는다 — 합성 스트림이라 의미가 없다. **이것을
한계로 명시한다.**)

**법칙 판정 (gate 아님 — 측정)**

- `k(r)` 이 `r` 에 대해 **단조 증가**하는가
- `k(0)` 이 0 에 가까운가 (메모리가 없으면 완전 은닉인가)
- `r = 27%`(= `fe25519_mul`) 에서 `k` 가 얼마인가 → **X25519 스티칭 이득의 근거**

**CE-1 (사전 고정): `k(0) ≤ 0.10`.**
메모리가 없는 스칼라 스트림조차 10% 넘게 샌다면, 누출의 원인은 메모리가 아니라
다른 데 있다는 뜻이므로 **법칙 해석을 포기하고 그 사실을 결과로 적는다.**

## 4. 위험·한계

1. 합성 스칼라 스트림이라 **실제 커널의 의존 구조를 반영하지 않는다.**
   이 프로젝트는 합성 proxy 를 불신한다(§ `slothy-2stream` 61.7% 사례).
   **따라서 `k(r)` 은 법칙이 아니라 "메모리 비율의 효과"만 분리한 값으로 쓴다.**
2. `.text` 배치(ITCM 예산). expCD 와 같은 조건이다.
3. 길이 156 은 expCD 의 lane 4(156 명령)와 맞춘 것이다.
