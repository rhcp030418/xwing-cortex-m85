# 데이터 누적 검증대장 — 최초 계획부터 현행 정본까지

- 대장 버전: 2026-08-31-r7
- 기준 시각: 2026-08-31 (Asia/Seoul)
- 범위: 최초 사전 계획, 선검증, 보드 측정, 실패·철회, 정정, 현행 채택값
- 목적: “가장 최신 파일이 맞을 것”이라고 가정하지 않고, 값이 생긴 순서와 교체 사유를 보존한다.
- 보류: 영문 문체 평가는 이 대장의 범위가 아니다.

이 문서는 현행 정본만 요약하는 `데이터_계보_아티팩트_정합성.md`의 앞단 장부다. 과거값을
삭제하지 않고 `역사`, `철회`, `대체`, `현행`으로 구분한다. 논문에 인용할 최종 수치는
`../논문_데이터_표.md`, 제출물 버전은 `데이터_계보_아티팩트_정합성.md`에서 다시 확인한다.

## 1. 기록 규칙

### 1.1 증거 우선순위

| 순위 | 증거 | 허용되는 결론 |
|---:|---|---|
| 1 | 원시 보드 로그, 동결 ELF/SREC, readback, KAT 출력 | 직접 실측·정확성·이미지 동일성 |
| 2 | 동결 아티팩트와 결과서 | 해당 실험 당시 판정과 재현 절차 |
| 3 | 생성기·어셈블리·호스트 solver 출력 | 정적 계수, 호스트 계산, 재생성 여부 |
| 4 | `논문_데이터_표.md`, 로드맵, 설계서 | 정리·파생·역사 복원 |
| 5 | 논문 원고와 리뷰 문서 | 소비 결과; 원자료의 대체물이 아님 |

충돌하면 위쪽 증거로 되돌아간다. 최신 수정 시각만으로 어느 파일도 정본으로 승격하지 않는다.

### 1.2 상태 표지

| 표지 | 뜻 |
|---|---|
| `실보드` | EK-RA8M1에서 cycle·정확성을 직접 측정 |
| `호스트` | CP-SAT, 정적 계수, QEMU·Unicorn 등; 실보드 성능이 아님 |
| `파생` | 직접 측정값을 산술 조합한 값 |
| `투영` | 호출 수·단가 등으로 확장한 값; 종단간 실측이 아님 |
| `역사` | 당시에는 사용됐으나 현재 대표값이 아닌 값 |
| `철회` | 전제·분모·정확성·계측 결함 때문에 결론으로 사용 금지 |
| `실패` | 사전 게이트 미달 또는 성능 악화 |
| `현행` | 현재 정본에서 채택하는 값 또는 판정 |
| `미측정` | 직접 확인하지 않았음 |

정확성 게이트를 실패한 후보의 cycle은 성능값으로 쓰지 않는다. 같은 보드의 재플래시 횟수는
보드 표본 수가 아니다. 이 프로젝트의 보드 개체 수는 현재 1대다.

### 2.3 파일별 카탈로그와 전수 데이터 패키지

§2의 전수 해시는 파일이 존재한다는 사실을 고정하지만, 사람이 각 파일의 역할과 계보를
읽기에는 부족했다. 이를 다음 두 층으로 폐합했다.

| 산출물 | 범위 | 용도 |
|---|---:|---|
| `전체_데이터_카탈로그.tsv` | source snapshot **6,531개** | 경로·archive 경로·크기·SHA-256·날짜·실험 ID·역할·증거 등급·단계·정본성·두 패키지 포함 여부 |
| `실험_계보_카탈로그.tsv` | 실험/내부 단계 **132개** + 후보 **73개** | 파일 수·로그/결과/사전등록/동결본 수·측정 등급·현행 판정·정본 경로 |
| `분모_표준화_카탈로그.tsv` | 표준 분모 **21개** + T 항목 매핑 **50개** | 원래 분모·표준 ID·환산식·비교 가능군·허용/금지 비교를 데이터별로 고정 |
| `데이터_패키지_제외목록.tsv` | **866개** | `.git` 내부와 재생성 Python cache를 경로·크기·SHA-256으로 고정 |
| `데이터_카탈로그.xlsx` | r26 snapshot | v32 핵심 artifact의 정본으로 사용하지 않음 |
| `all-data-upload.zip` | r26 snapshot | v32 핵심 artifact의 정본으로 사용하지 않음 |

source snapshot은 자기참조가 생기는 전체 작업공간 manifest, 카탈로그 생성물, 전수 ZIP
자신을 행에서 제외한다. 이 9개 이름은 `데이터_카탈로그_요약.json`에 고정하며, 최종
물리 파일 존재와 해시는 바깥의 `전체_파일_SHA256.tsv`가 담당한다. 따라서 “빠뜨려서
제외”와 “자기참조라 별도 계층에서 검증”을 구분한다.

전수 패키지의 포함 규칙은 원시 로그·ELF/SREC·결과서·소스·동결본·`_보관`·vendor·문헌·
논문 파생물 전부다. 연구 데이터가 아닌 Git 내부와 재생성 cache만 corpus에서 제외한다.
v32 핵심 제출은 `artifact-upload.zip`의 원본 크기·SHA-256, ZIP CRC, 중복 경로와 내부
manifest를 검증한다. r26 전수 ZIP은 해당 시점의 `all_data_included=Y` 집합과
`corpus/A주제/` 집합의 정확한 일치를 검사한다.

| Lenngren 양보 | Fiat 교체비 약 532k를 양보비처럼 해석 | CR mul y1이 3.88% 빠름 | **DC E2E U′는 3.94~5.75% 느림** | micro와 E2E를 분리해 직접 측정 |
| PMU 계수 | 초기 보드에서 event 0 | DD DWT-off self-test와 wrap 재측정 | **퇴직 명령 9.23~27.08% 감소; stall class 미확정** | 측정 충돌을 분리해 instruction만 직접 폐합 |
| A/B 배포 자원 | expCJ 결합 section만 존재 | DE 비엄격 분리에서 미사용 객체 잔존 | **DE 최소 프록시 비휘발 +34,308 B, 정적 RAM +2,040 B, max stack 차이 0 B** | 독립 링크·명시적 manifest·보드 canary로 폐합 |

주 F/U의 원시 효과 부호는 `g=100(F-U)/F`라 음수가 회귀다. 위 표는 가독성을 위해
회귀 크기를 양수로 썼다. `expCV` 5회와 `expCZ` 2회는 각 재플래시마다 AB/BA가 있으므로
연산별 F 셀 14개, U 셀 14개, **paired effect 14개**다. 세 연산 합계는 42개다.
F/U 절대 셀 28개를 paired effect 28개라고 부르면 안 된다.

## 7. 갱신 절차

새 실험이 생기면 다음 순서를 지킨다.

1. 사전등록·실행 로그·ELF/SREC/readback·결과서의 실제 존재를 확인한다.
2. 정확성 게이트를 먼저 기록한다. 실패하면 cycle을 성능 장부에 넣지 않는다.
3. 이 문서의 날짜별 끝에 새 행을 추가한다. 기존 행을 덮어쓰지 않는다.
4. 교체되는 값은 §4 승계 사슬에 `최초→중간→현행`으로 추가한다.
5. `../논문_데이터_표.md`의 대응 T 항목과 대조한다.
6. `데이터_계보_아티팩트_정합성.md`의 현행 집합·해시·제출물 버전을 갱신한다.
7. `verify_data_ledger.ps1`로 새 결과서·사전등록·로그·아티팩트뿐 아니라 전체 파일명의
   `exp*`, 후보군 K/W/X/T 73개, T 대응을 검사한다.
8. `build_data_catalog.py`로 파일·실험·분모 카탈로그를 다시 만들고 `데이터_카탈로그.xlsx`의
   Summary·QC 수식과 7개 시트 렌더링을 검사한다. 분모 매핑은 T1~T49와 T28b 50개를
   정확히 한 번씩 포함해야 한다.
9. `package_all_data.py`로 포함 원본의 hash drift, 내부 manifest, corpus 집합을 검증하며
   `all-data-upload.zip`을 다시 만든다.
10. `verify_all_files.py`로 최종 manifest의 전 파일 경로·크기·SHA-256, SREC
    checksum/overlap, ELF/object/PDF/PNG signature, ZIP/XLSX CRC를 검사한다.
11. 경로 존재, paired count, 표의 산술을 자동 검사한다.

이 절차를 통과하지 않은 새 파일은 “최신처럼 보이는 후보”일 뿐 정본이 아니다.
