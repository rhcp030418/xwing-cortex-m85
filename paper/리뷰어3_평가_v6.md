## 0. 한 문장

이 논문은 "파생 미점유 용량이 스티칭 이득을 예측하지 못했다"고 주장하지만, 실제로 시험한 후보 U는 **X25519의 약 23%와 Keccak의 약 28%만 겹친** 통합이고, 종단간 회귀의 **약 78%는 겹친 구간 바깥**에서 발생했다. 따라서 이 논문이 실증한 것은 "미점유 용량 ≠ 이득"이 아니라 "**이 특정 상태기계 통합의 wrapper 비용이 작은 중첩 이득을 삼켰다**"이며, 두 문장은 다르다.

## 1. 판정을 좌우하는 문제 (P0)

### 1.1 중심 음성 결과가 후보 설계의 산물인지 아키텍처의 산물인지 분리되지 않았다

본문 자체의 숫자로 계산하면:

| | 값 | 출처 |
|---|---|---|
| U가 겹친 Keccak | permute4 3회 × 4 lane = 12 순열 (dummy lane 포함) | 711–714행 |
| 연산당 필요한 Keccak | 43–45 순열 | 208행 |
| U가 겹친 X25519 | 배치당 96 step × 3 = 288 step-phase | 656–659행 |
| ladder 전체 | 255 bit × 5 phase = 1,275 step-phase | (5-phase 상태기계, 본문 미기술) |
| keygen F→U 손실 | 26,386 cycle | tab:final |
| 그중 세 배치 국소 회귀 | 5.83–5.87k (22%) | 696–697행 |
| **겹친 구간 바깥 손실** | **≈20.5k (78%)** | 산술 잔차 |

즉 legacy 21–26% 상한에서 3.00–5.07% 상한으로 떨어진 이유의 대부분은 **마이크로아키텍처가 아니라 파트너 coverage를 12/43로 잡은 설계 선택**이고, 회귀의 대부분은 스티칭된 코드가 아니라 `finish_all`·queue·qsave/qrestore·phase dispatch 등 **미기술 wrapper**에서 났다. 본문은 이를 "원인은 미측정"(700행)으로 처리하지만, 결론(928–936행)과 초록은 이를 "미점유 용량이 충분조건이 아니다"라는 일반 명제로 승격한다. 현재 증거로 지지되는 문장은 "이 후보는 wrapper 비용 때문에 졌다"까지다.

**요구:** (i) 왜 3 배치만 겹쳤는지, 나머지 31–33 순열과 987 step-phase를 겹치지 않은/못한 이유를 명시. (ii) 세 `permute4` 전후 checkpoint로 in-context 배치 손실과 wrapper 손실을 실측 분리. (iii) 제목·초록·결론을 "후보 통합의 wrapper 비용" 수준으로 낮추거나, coverage를 늘린 두 번째 후보로 반증 시도.

### 1.2 시험 대상 U가 논문에 기술되어 있지 않다

U에 대한 본문 설명은 660행 한 문장("같은 job 수와 상태 전이를 유지하면서 두 스트림을 한 함수 안에서 섞는다")뿐이다. 심사위원이 알 수 없는 것:

- U를 SLOTHY(4절)가 만들었는가, 수작업 지퍼가 만들었는가? → 4절 기여와 5.2절 결과의 연결이 본문에 없다. 연결이 없으면 4절은 별개 논문이다.
- 교차 세밀도(명령 단위? 라운드 단위?), 레지스터 분할(-ffixed 몇 개?), 스필 수, 5-phase 상태기계가 무엇인지, `96 mod 5 = 1`로 배치마다 phase가 바뀌는 구조.
- U의 code size·stack 증분.

동적 명령 +979/+2,200은 있지만 **어디서** 늘었는지 class vector만 있고 심볼별 귀속이 없다. 재현 부록에 있다고 본문 기술 의무가 면제되지 않는다.

### 1.3 F는 격리 기준이지 순차 기준이 아니다 — 표에 S가 없다

부록 B가 x4를 "scalar 경로보다 2–3% 느려 기각"했다고 밝히면서, 핵심 표(tab:final)는 F/U만 싣는다. 독자는 "최선의 순차 구현 S 대비 U는 몇 %인가"를 알 수 없다. S/F/U 세 열을 같은 표에 넣지 않으면 "스티칭이 순차보다 느리다"는 헤드라인이 성립하는지 판정할 수 없다. 5차 리뷰 4.5절 지적이 v6에도 반영되지 않았다.

## 2. 방법론 (P1)

### 2.1 독립 표본 n=2에 소수점 셋째 자리

tab:cumulative의 25.967 / 20.249 / 11.224 / 18.298과 tab:final의 [−1.988,−1.979]는 독립 플래시 2회에서 나온 수다. 범위 보고로 바꾼 것은 좋지만 자릿수가 정밀도를 과장한다. 둘째 자리로 자르고, cold boot ≥5회·보드 2대 없이 "재현"이라는 단어를 쓰지 말 것.

### 2.2 IPC라는 단어를 쓰지 말 것

파생 IPC = (별도 run의 보드 cycle) / (다른 run의 single-step 명령 수 또는 Unicorn 명령 수). 본문은 매번 "파생"을 붙이지만 표 열 이름·그림 2·초록 첫 줄에서 IPC로 읽힌다. `I/C` 같은 중립 기호로 바꾸고 IPC는 PMU 측정에만 예약할 것. 특히 single-step 실행은 캐시·분기예측 상태가 정상 실행과 다르므로 명령 수는 같아도 이를 정상 run cycle과 나눈 값은 물리량이 아니다.

### 2.3 $2C-I$ 그림(그림 2)은 여전히 슬롯 trace처럼 보인다

caption에 "개념도"라 썼지만 그림은 매 cycle 슬롯 1이 비어 있다. 정직한 그림은 막대 하나에 "명령 수로 채워진 51%/설명되지 않은 49%"다. 시계열 격자는 삭제 권고.

### 2.4 통계 처리 부재

ABBA 네 pair 중앙값 범위만 있고 셀 내부 100회 분포(IQR, min/max)가 없다. 0.00683% drift 한 줄로는 interrupt·cache 상태 미통제를 대체할 수 없다. 최소한 per-cell IQR과 timed span 내 interrupt count를 부록 표로.

### 2.5 상수시간 절(7절)은 결과가 아니라 체크리스트다

"두 입력에서 979,065 cycle 동일"은 **한 커널**·**두 입력**이다. 종단간 U·B에 대해서는 구조 감사뿐이다. 이 절이 지지하는 주장은 "새 비밀 의존 분기를 넣지 않았다"까지이며, 그렇게만 쓰면 절 하나가 아니라 한 단락이다.

## 3. 범위·서술 (P2)

1. **초록이 너무 길다** (~430자 → LNCS 관행 150–250 단어). 숫자가 12종 이상 나열되어 무엇이 주장인지 알 수 없다. 음성 결과 한 문장 + 범위 한 문장 + 보조 사례 한 문장으로.
2. **draft-10 6절은 별개 논문**이다. 스티칭 축이 없고, leave-one-out이 없으며, 본 논문 질문(서론 65행)과 무관하다. 표 하나·한 단락으로 줄이거나 분리 투고. 지금은 음성 결과보다 양성 결과가 더 길어 논문의 정체성이 흐리다.
3. **fiat-crypto 미인용.** "Fiat X25519"를 30회 이상 쓰면서 fiat-crypto 논문(Erbsen et al., S&P 2019)이 참고문헌에 없다. Fiat 구현이 무엇인지(10×25/26 limb?) 본문 설명도 없다.
4. **관련 연구 15건은 얇다.** M-profile X25519(Fujii–Aranha, Haase–Labrique), MVE Keccak/ML-KEM 최적화, 음성 결과 방법론 논문과의 비교 없음. Intel 백서 하나에 기대어 "스티칭"을 정의한다.
5. **용어 흔들림:** 미점유 용량 / 빈 슬롯 / 구조 용량 / 미설명 용량이 같은 것을 가리킨다. 하나로.
6. **"보수적(관대한) 상한"**(320행): 보수적과 관대한은 반대말이다. 독자에게 어느 방향인지 매번 설명해야 하는 표현은 잘못된 표현이다. "실제보다 큰 상한(느슨한 상한)"으로.
7. **식 (3)의 $n_X C_X$ 항**은 어떤 연산에서도 활성화되지 않는다. 왜 넣었는지 설명 없으면 삭제.
8. 부록 A는 새 정보가 없다(본문 반복). 삭제 가능.

## 4. 유지되는 것

- 동결 ELF·같은 wrapper·두 플래시·네 pair에서 U < F 방향 일치. 이 사실 자체는 견고하다.
- 명령 분류기 수정 후 F/U 전량 계수, 공식 vector 1 전량 대조, 자립 Overleaf 빌드 — 이전 재심 항목은 실제로 닫혔다.

### 리뷰어 추정 중 실측으로 정정된 것

7절 1.1에서 "회귀의 약 78%가 겹친 구간 **바깥**"이라 추정했으나 **틀렸다.** expCO/expAI
checkpoint는 손실이 전부 융합 구간 **안**에서 나고 잔여 구간은 옮긴 만큼 짧아짐을 보였다.
정확한 서술은 "wrapper가 비쌌다"가 아니라 **"옮긴 작업이 배치 안에서 15~29% 더 비쌌다"**이다.

### 새로 생긴 한계 (정직하게 기록)

- expCP의 총 손실 비교는 5배치 기준형 잔여 구간의 +100k 꼬리(반복의 35~40%) 때문에
  **추정량 의존**이다. 중앙값은 ×1.50 악화, 평균은 ×0.99 동일. 따라서 "커버리지를 늘리면
  총 손실이 선형으로 는다"는 문장은 쓰지 않았고, 판정은 꼬리 무관 양으로만 세웠다.
  꼬리의 cache 메커니즘은 PMU 불능으로 **미측정**.
- 손익분기까지 23배치라는 수치는 두 점의 **외삽**이다.

### 판정 갱신

본회의 Reject 사유였던 "제시한 증거가 질문에 답하지 않는다"는 해소됐다. 이제 논문은
(i) 손실이 어디서 나는지, (ii) 왜 나는지(옮긴 작업이 배치 안에서 더 비쌈),
(iii) 파트너를 넓혀도 그 성질이 유지되는지를 각각 실측으로 답한다. 남은 약점은 단일
보드 개체와 배칭 상한 77%까지 가지 않은 커버리지이며, 둘 다 장비·공수 항목이지
논증 결함이 아니다. → **워크숍/negative-result 트랙 Accept, 본회의 Borderline.**
